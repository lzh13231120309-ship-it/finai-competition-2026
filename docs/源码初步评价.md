# 同伴作品初步评价

本轮为源码检查与本地基础验证，不是完整产品审计或金融准确性验收，未消费模型 API。

## 可复用的基础

现有项目包含 FastAPI 后端、静态网页、模型提供方配置、聊天流式响应、文件解析、知识库、Skill/MCP 和本机工具。数据库记录中有工具调用字段。因此可以沿现有结构开发，无需重做整个页面。

## 为比赛还需补齐的部分

- parsers.py 的 PDF 逻辑依赖文字层。扫描件只返回提示，尚未自动 OCR；此次比赛通知本身即为真实扫描件案例。
- Excel 解析有行列和总文本长度上限，财报处理应显式记录截断，并核对多页表格和合并单元格。
- 通用 calculator 与工具调用记录不等于已经有财务口径规则、估值公式和完整审计链。需对每个结果保存输入、单位、报告期、公式、来源和执行信息。
- 原应用 config.py 明文保存本地 API Key；原 data 不纳入仓库。源码中的默认配置不含实际密钥。
- 原应用默认允许本机文件和命令工具。比赛受控运行应限制到授权材料目录，现阶段保持本机访问，不直接发布为公共服务。
- 第 5 项需要草稿句子定位、原始证据对应、错误类别、建议值、置信或复核标记，并评估误报。
- 第三方依赖、现有代码来源和可分享数据许可需要团队补充说明；目前不虚构许可证，也不将原有成果称为本轮新开发。

建议先新增业务模块和结构化结果页，再按实际需要改善页面。当前没有改写现有功能，也未把通用聊天说成金融任务已经完成。
