# 财务报告分析（竞赛选题 ②）

用可追溯的事实回答财务问题，把**源数据、公式、财务解释、待核验事项**四层分开写。

## 一、分工与前置阅读

| 技能 / 资料 | 作用 |
| --- | --- |
| **本技能** | 选题② 入口：固定章节结构、口径定义表、缩放禁令、自检清单 |
| `listed-company-financial-analysis` | 深度规则与边界（含 `references/metric-rules.md` 的指标边界表） |
| `forensic-anomaly-screening` | 异常信号筛查（做风险筛查前必读） |
| 知识库「三表勾稽与指标口径」 | 恒等式清单、指标公式、异常阈值 |
| 知识库「会计口径与数据陷阱」 | 单位、期间、比率、类现金口径的成因与修法 |

本技能负责"报告长什么样"，`listed-company-financial-analysis` 负责"每个判断的边界在哪"，**不重复定义**。

## 一之二、确定性引擎的能力边界与调用入口

**入口**：`analyze_financial_report(filenames=[...])`。多份财报**一次传完**——季报 + 上年同期年报一起传，
引擎才能算同比与可推导单季。返回 `run_id` / `facts` / `metrics` / `checks` / `review_queue` /
`formula_catalog` / `disclosure_map`，并自动导出 Excel/JSON/Markdown。
补充段（`server/financial_gaps.py` 随主分析自动产出，无需另调工具）：
`quarter_facts`（单季）、`restatement_changes`（口径已知的重述候选）、
`restatement_suspects`（口径未知的差异）、`reason_candidates`（业绩原因段落定位）、`gap_notes`（为什么没产出）。
**所有金额与指标必须取自这里**，模型不取数、只解读；结果被预览截断时用 `read_financial_run` 分页读全量。

| 能力 | 引擎是否支持 | 报告里怎么写 |
| --- | --- | --- |
| 同比（yoy） | ✅ `<科目>_yoy`，公式 `(current − prior_year) / prior_year` | 直接用。**上年基数为零或负数时引擎不报百分比**，只报绝对增减额——不得自行补一个"负增长百分比" |
| 可推导单季 | ✅ 累计数相减；另有 `quarter_facts` 段从年报「分季度主要财务指标」表直接抽四个单季值 | 直接用。重述/调整口径不一致时引擎拒绝推算并进 `review_queue`，此时写"该期单季不可推算"并说明原因 |
| 环比（qoq） | ✅ `code` 以 `_qoq` 结尾的指标（`derived=true`），只连**相邻单季**（同年差 1 季，或跨年 Q4→Q1，公式里写"跨年"） | 可以写，但必须写明是**本项目补充计算**（`derived=true`），与引擎原生指标分开表述。基数非正时不报百分比，只有 `_qoq_change` 绝对增减额 |
| 现金流与利润背离 | ✅ `cash_conversion` = 经营现金流净额 / 净利润；`weak_profit_cash_conversion`（< 0.5 触发）、`negative_operating_cash_flow` 信号 | 直接用，并说明季节性、营运资金与收款安排 |
| 勾稽核验 | ✅ `checks` | 原样报出，不得只说"已核验" |
| 经验阈值信号 | ✅ 如扣非前后归母差额占比 > 30%、某科目增速超营收增速 20pp | 是**待核验信号**，不是结论 |
| 非经常性损益 | ⚠️ 有**汇总口径**：`nonrecurring_profit_share` =（归母 − 扣非归母）/ 归母，带 `nonrecurring_profit_concentration`（> 30%）信号；**不解析附注逐项明细表** | 可引用汇总占比；逐项明细（政府补助、资产处置、公允价值变动等）需人工读附注并给页码，**不得声称已自动抽取明细** |
| 会计口径变更 | ⚠️ `restatement_changes` 给**口径已知**组的差异（差额/比值/两值来源/`rebuilt_table` 标记），`cause` 恒为 `null`；口径未知的进 `restatement_suspects` | 只有 `restatement_changes` 可写成重述候选；**`restatement_suspects` 不得当口径变化引用**（可能是合并/母公司混用）。成因必须人读附注并标为**推断** |
| 业绩变化原因 | ⚠️ `reason_candidates` 只给**段落位置**（页码 + `evidence_id` + 命中关键词 + 原文摘录），不做归纳 | 归因由模型读原文后写，必须标为**推断**。`reason_candidates` 为空时，写"报告未披露**或**该部分未被解析到"——**不得写成"公司未披露"** |

**为什么要写清这条边界**：评审可能直接问"有没有做环比、有没有做业绩归因"。
诚实回答"环比与单季由本项目补充计算（`quarter_facts` / `_qoq`，`derived=true`），
非经常性损益明细与口径变更成因仍由人工读附注完成"，比含糊地说"我们做了"安全得多，
也不会被追问细节时穿帮。**宁缺毋滥，不猜。**

**分季度表的勾稽纪律**（唯一新增的取数路径，必须知道它的红线）：
- 年份不靠猜——取自**同一份文档**里该科目的年度事实（期末 12-31）；
  找不到年度参照就不抽取，并在 `gap_notes` 里说明。
- 每行都用 **「四季度之和 == 年度值」** 勾稽（容差 `max(0.5×量级, 1)`）：
  通过 → `status=verified`，可参与环比；不通过 → `status=needs_review`，
  **只记录、不参与环比**，并进 `review_queue`（`quarter_sum_mismatch`）。
- 只收**期间流量类**科目（营业收入 / 归母净利润 / 扣非归母净利润 / 经营现金流净额）。
  资产负债类（总资产、归母净资产）是时点值，没有环比语义；
  每股收益也不收——季度 EPS 之和与全年 EPS 因股数变动和四舍五入对不上，收了会把整表判为未通过。
- 表头支持「第一季度…第四季度」与 `Q1…Q4`；缺任一季度的行整行跳过（不足四季度不推算）。

## 二、报告固定章节结构

不按这个结构写，等于放弃"分析逻辑严密性"与"证据支撑充分性"两项得分。

```
0. 一页速览          —— 结论先行，但每个数字都标出处
1. 数据基础与口径声明 —— 公司/期间/范围/币种/单位/审计状态/重述状态 + 覆盖了哪几张表
2. 盈利能力          —— 毛利率、净利率、ROE/ROA（杜邦拆解）+ 单季/环比趋势（标 derived）
3. 现金流质量        —— 净利润 vs 经营现金流背离分析、现金转化率、自由现金流
4. 资产负债与偿债能力 —— 资产负债率、流动/速动/现金比率、有息负债、净现金/净债务
5. 营运效率          —— 存货/应收/应付周转与天数、现金转换周期
6. 异常信号与待验证假设 —— 每条 = 触发事实 + 期间 + 比较基准 + 证据 + 未排除解释
7. 数据缺口与附注索引 —— 三类缺口分列，凡"未抽取"必须给附注定位
8. 附录             —— 事实表 / 指标表（含公式）/ 勾稽核验表 / 复核清单
```

**第 0 节不是"摘要"，是"结论 + 证据锚点"。** 每个结论后面跟 `（第 N 页）` 或 `（指标 code=xxx）`，让评委能一步跳到证据。

**单季/环比放在第 2 节，会计口径变化放在第 1 节（重述状态）与第 6 节（异常信号）。**
三处都要标清来源：`quarter_facts` / `_qoq` 是本项目补充计算（`derived=true`），
`restatement_changes` 是口径已知的差异候选、`cause` 为 `null`，
`reason_candidates` 只提供段落位置——归因文字由你写并标为推断。

## 三、口径定义表（先声明，再计算）

报告里出现下列指标时，**先在第 1 节把采用口径写清楚**，第 8 节附录里给出公式与实际操作数。

| 指标 | 本项目采用口径 | 明令禁止 |
| --- | --- | --- |
| 毛利率 | `(营业收入 − 营业成本) / 营业收入` | 用"营业总收入"混入其他业务收入后不改标签 |
| 净利率 | 净利润 / 营业收入 | 归母净利润算出的比率不改标签就叫"净利率" |
| ROE | 归母净利润 / **平均**归母权益（期初+期末)/2 | 用期末权益单点；把简化 ROE 称为"加权平均 ROE" |
| ROA | 净利润 / 平均总资产 | 期初缺失时用期末代替后仍称"平均" |
| 资产负债率 | 总负债 / 总资产 | 把"总负债"与"有息负债"混用 |
| 速动比率 | `(流动资产 − 存货) / 流动负债` | 不声明这是简化口径 |
| 现金转化率 | 经营现金流净额 / 净利润 | 净利润为负时套常规结论 |
| 周转天数 | 区间实际天数 / 周转次数 | 把半年指标机械 × 365 当全年 |
| 自由现金流 | 经营现金流净额 − **abs(购建长期资产支付的现金)** | 减"全部投资活动现金流"；不取绝对值导致负 CAPEX 变相加回 |
| EBITDA | 税前利润 + 财务费用 + 折旧摊销合计 | 从净利润简单加回净财务费用就称 EBITDA |

**期间一致性**：分子是区间值、分母是时点值的指标（周转率、ROE、ROA），分母必须用**期初期末平均**；用期末单点会系统性偏高。半年报/季报的周转类指标**不做年化**，并在公式里写明 `period basis, not annualized`。

## 四、单位、每股与比率的缩放禁令（最高频、最致命）

这三类错误不会报错、不会触发缺失，只会让数字静默地差 1000 倍或 10000 倍。

### 1. 每股类指标不是金额

`basic_eps`、`diluted_eps`、`dividend_per_share` 的 `unit` 是 **`元/股`**，与报表列报单位（千元/百万元）无关。

> **禁止把 EPS 按"元 ÷ 1000"换算成千元。**
> 每股 1.411 元 ÷ 1000 = 0.001411，四舍五入到两位小数就成了 `0.00` —— 报告里出现 `每股收益 0.00 元` 就是这个原因。

### 2. 比率类指标不是金额

`unit = ratio` 的值是**比例小数**：`0.6053` 就是 60.53%，**不是 6053%**，也不是 0.6053 元。**任何比率都不得按千元/百万元缩放。**

### 3. 原文单位不得跨表混用

工具返回的 `facts` 是**原文列报数值**，单位见该行第 3 项。同一科目可能同时存在「千元（主表）」与「百万元（摘要页）」两个来源，这是**列报精度差**，不是错误。跨单位比较前必须先归一到同一单位，并在报告里说明换算过程。

**自查信号**：若算出 `ROA > 100`、`资产周转率 > 10`、`毛利率 > 100%`，**第一个要怀疑的是单位，不是财务造假**。

## 五、类现金与净债务口径

"净现金"是极容易被"顺手放宽"的口径——把按公平值计入损益的理财（FVTPL）也算进类现金，净现金会虚增几十亿。

必须使用**公式里逐项列出科目名**的口径，不得自己定义"类现金"：

| 口径 | 公式 | 特点 |
| --- | --- | --- |
| 现金及银行结余 | `cash` | 最窄，年报主表口径 |
| 类现金 | `cash + long_term_deposits` | 保守，含长期银行存款 |
| 有息负债 | `borrowings + lease_liabilities` | 含租赁负债 |
| 净现金 | 类现金 − 有息负债 | **不含 FVTPL 理财** |
| 净债务 | 有息负债 − 现金 | 更保守 |

**若确实要采用含 FVTPL 理财的宽口径**：必须在报告中**显式说明**"本口径将 X 亿元 FVTPL 理财计入类现金"，并同时给出窄口径结果，让读者自己判断。**不得静默放宽。**

同一笔债务可能在不同来源各出现一次（财务状况表的「計息借貸」经分节拆成短期借款、附注又整行列一次），简单相加会把债务算两遍。**采用工具返回的口径指标，不要自己拼加。**

## 六、数据缺口必须分三类（与选题①同一纪律）

| 类型 | 判据 | 写法 |
| --- | --- | --- |
| 文档确未披露 | 已全库检索确认原文没有 | "原文未披露" |
| **本工具未抽取** | 原文有，工具字段覆盖不到（附注、MD&A、分部） | "**见附注 X（第 N 页）**" |
| 待复核 | 抽到但冲突/低置信度/口径不明 | 进复核清单，附候选值与理由 |

工具返回的 `disclosure_map` 就是为第二条准备的：它把常见分析需求映射到**本次文档里已定位到的披露位置**。报告里写"数据缺口"之前，先查 `disclosure_map`；**只要它在里面，就必须写成"见附注 X 第 N 页"，不能写成缺口。**

同理，`review_queue` 里的事项是**待复核**，不是**已排除**。不能删掉待复核事项后宣称"报告已全部核验"。

## 七、异常信号的表述纪律

一条合格的风险信号必须包含五要素：**触发事实 + 期间 + 比较基准 + 证据 + 未排除解释**。

- "净利润为正而经营现金流为负" = 可复核现象 ✅
- "可能受应收增长或季节性影响" = 需验证假设（要标注"待验证"）✅
- "财务造假" = **不能由前两者推出** ❌

其他同类纪律：
- 中标金额 ≠ 已确认收入；质押 ≠ 违约；负经营现金流 ≠ 偿债困难。
- 审计意见、持续经营、诉讼、关联方事项，**只能在原文披露时引用**；未检索到不能写"无风险"。
- 启发式阈值要显示其定义，不得称"行业通用标准"或"监管红线"。
- 工具给出的 `risk_score` 只用于排序，**禁止表述成"财务造假概率"**；`severity` 是严重度、不是置信度。

## 八、交付前自检清单

### 8.1 三类"抄错"必须逐项核对（每一类都实测踩过）

报告里出现的每一个数字，只有两种合法来源：**工具返回值原样抄录**，或**报告内明示公式的计算结果**。下面三类最容易出错，交付前必须逐项核。

**① 计数类数字必须与工具字段一致，且明细之和等于总数。**
工具返回的 `fact_count` / `verified_count` / `metric_count` / `check_summary.total` / `review_count` 是权威值，直接抄，不要自己数。若同时给了分类明细，**明细必须加总等于总数**。
> 实测反例：某版报告第 2 节写「待复核事项 19 项」，第 8 节明细却列了
> `unresolved_metadata 7 + statement_mismatch 3 + subject_alias_collision 1 + sign_convention_mismatch 2 + excluded_fact 13 = 26`，
> 与工具返回的 `review_count: 26` 也不一致。总数与明细对不上，评审一眼就能看出报告没自检。

**② 每一个「—」「未计算」「未披露」都要能说清理由。**
写「—」之前，先在工具返回的 `metrics` 里按 `(指标代码, 期间, 口径)` 查一遍：
- 查得到值 → **必须写值**，写「—」就是漏读；
- 查不到 → 才写「—」，并在缺口章节说明原因（原文确未披露 / 缺可比期基础 / 本工具未抽取）。

**同族指标不要张冠李戴**：`roe`（母公司拥有人应占溢利 ÷ 平均母公司权益）与
`roe_total`（年内溢利 ÷ 平均总权益）是两个代码、两条公式；`roa` 的分母是总资产。
某期只有其中一个有值是正常的（缺可比期科目），此时应写另一个的值并注明口径，
而不是整格写「—」。同类还有 `net_cash`（合并/母公司两套算式）、
`cash_and_deposits`（缺长期银行存款的年度退化为 `cash`）——`formula_catalog` 里
值是多版本列表时，**必须对齐该期间/口径的那一条算式**。

**③ 同比、占比、天数等派生值必须能在报告内复算。**
每个派生值都要在公式区给出操作数，读者用报告里的数字能算出同样的结果。
不要在正文里出现公式区没有的第三个数字。

### 8.2 清单

- [ ] 报告按第二节八节结构组织，第 0 节结论都有证据锚点
- [ ] 第 1 节声明了公司/期间/范围/币种/单位/审计状态，并列出覆盖的报表
- [ ] 所有指标在第 3 节口径表里有对应定义，附录给出公式与实际操作数
- [ ] **没有任何每股指标或比率被按千元/百万元缩放**
- [ ] 净现金/净债务用的是逐项列名的口径；放宽口径时已显式说明
- [ ] 周转率、ROE、ROA 的分母用的是期初期末平均，且标明了"未年化"（若为中期报告）
- [ ] 数据缺口已分三类；凡"未抽取"都给了附注页码
- [ ] 风险信号都写了五要素；没有把风险分说成造假概率
- [ ] 附录含事实表、指标表（带公式）、勾稽核验表、复核清单
- [ ] 交付物含结构化文件（Excel/JSON/Word），不是只有对话正文
- [ ] **所有计数类数字与工具字段一致，分类明细之和等于总数**（见 8.1 ①）
- [ ] **每一个「—」都能追溯到"工具确实没有该 (代码, 期间, 口径) 的值"**（见 8.1 ②）
- [ ] **同族指标（roe / roe_total、net_cash 合并与母公司）没有混用口径**（见 8.1 ②）
- [ ] **每个派生值都能用报告内给出的操作数复算出来**（见 8.1 ③）
- [ ] **单季/环比指标都标了 `derived=true`（本项目补充计算），没有混进引擎原生指标的表述**
- [ ] **没有把 `restatement_suspects`（口径未知）当成口径变化或重述来引用**
- [ ] **口径变化的成因、业绩变化的原因都标为推断，没有写成程序结论**
- [ ] **`reason_candidates` 为空时写的是"报告未披露或该部分未被解析到"，不是"公司未披露"**
