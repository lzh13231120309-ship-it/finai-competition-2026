# 财务法证异常筛查

目标是把"这份报表哪里可能有问题"从主观印象变成**可复现的规则命中 + 可追溯的证据**。宁可少报，不可把正常波动写成造假结论。

## 执行入口

先检查当前环境真实可用的工具，不要凭本技能的描述假定工具存在。

- **本地金融 Agent**：按 `analyze_financial_report` → `forensic_scan` → `read_financial_run` 的顺序调用。三个工具都必须用真实的 `run_id` 串起来，不要凭记忆重述上一步的结果。`forensic_scan` 的 `run_id` 传上一步分析运行的 ID；`peer` 参数传同行分位（见下）。
- **其他 harness**：在用户指定的本项目目录先运行 `python -m server.finance_cli --help`，再查看子命令的 `--help`。项目虚拟环境存在时优先用 `.venv/bin/python`。以帮助输出为准，不猜测未列出的选项。
- **缺少项目工具**：可以按可见证据做人工规则核对，但必须明确写出"哪些结论未经过项目法证引擎复算"，不要声称已生成风险评分。

## 工作流程

1. **取得已核验事实**：调用 `analyze_financial_report`。若返回里 `status` 不为 `verified` 的事实占多数，先解决提取问题（口径、单位、期间），再跑法证。**用待核验数据跑出来的风险分没有意义**，且会污染后续估值。
2. **跑规则引擎**：调用 `forensic_scan(run_id, top_k)`。先用默认 `top_k`，确认命中数量合理后再决定要不要扩大。
3. **补同行分位**：先用 `peer_benchmark(run_ids=[目标公司, 同行1…4], target_run_id=目标公司)`
   把各公司的分析运行算成一张分位表（中位数 / P25 / P75 / 极值），
   返回的 `rule_payload` **直接**作为 `peer` 参数传给本工具（`peer_payload` 也可以，
   引擎内部按 `RULE_PEER_METRIC` 自动翻译）。
   - 竞赛 MVP 要求**五家**同行；至少两家才有意义，一家时报错而不是硬算。
   - `peer_extremeness` 按**四分位距（IQR）**归一化：落在 [p25, p75] 区间内记 0 分
     （同行区间内不算极端），超出区间每 1 个 IQR 记约 33 分，3 个 IQR 以上封顶 100。
     旧口径只看中位数，会把正常的中位水平也报成异常 —— 这是已修掉的实质缺陷。
   - **键必须对得上**：法证规则按 `rule_id` 查同行分位（R_MARGIN_01…），
     而分位表按指标代码索引（gross_margin…），中间靠 `forensics.RULE_PEER_METRIC`
     翻译。曾经两边键不同名，`peer_extremeness` 恒为中性 50 分 —— 表面上"接了同行数据"，
     实际上同行对排序毫无影响。用 `rule_payload` 可以避免这类静默失效。
   - 返回里 `aligned=false` 表示各公司报告期不一致，差异里混着行业周期，
     必须在交付物里说明，不能当成经营质量差异。
   - `outliers` 列出目标公司显著偏离同行的指标，这些是**优先复核项**。
   - **没有同行数据时不要编造**，留空即可，引擎会把该项取中性 50 并在结果里标记
     `peer_data_missing`。
4. **逐条复核发现**：读 [法证规则库](references/forensic-rules.md) 核对阈值方向与所需证据；用 `read_financial_run(run_id, section='findings')` 读取完整字段（`risk_score` 五因子分解、`evidence_ids`、`counter_evidence`、`open_questions`、`valuation_link`）。
5. **做反证检索**：每条发现都带 `counter_evidence`（能推翻它的检索方向）与 `open_questions`（还没解决的问题）。**必须真的去查**：回到 `inspect_document` 读对应附注、管理层讨论、关联方与分部信息。查完把结论写进交付物——包括"查了、但没找到解释"这种结果。
6. **交付**：按风险分排序输出发现清单，写清每条的支持证据、反证检索结果、未解问题、以及它会传导到哪个估值参数。`read_financial_run(run_id, section='tieout_diagnosis')` 给出勾稽失败反查，若 `resolution` 是 `unit_misplacement`，写明建议的单位量级与依据，**但不要自动改数**。

## 五因子评分口径

`risk_score = 0.30×magnitude + 0.25×persistence + 0.20×peer_extremeness + 0.15×cash_impact + 0.10×disclosure_uncertainty`

- 各因子取值 0–100，分数越高风险越大；总分是加权和，不是概率。
- `persistence` 看连续多少期成立，单期异动得分天然低。
- `cash_impact` 只对真正影响现金流或净资产的规则加权（见规则库的标记）。
- `disclosure_uncertainty` 反映附注是否说清了这件事；**说不清本身就是风险**，但也可能是单纯的披露简略，需要在交付物里区分。
- 同一规则跨年命中会被合并为一条，`periods` 列出所有命中年份，取最高分的期作为代表。

## 关键约束

- 规则是**启发式筛查**，不是监管标准，也不构成造假认定。交付物里用"待核验事项""需要解释的差异"，不要用"造假""舞弊"。
- 阈值是经验值。行业差异很大的科目（毛利率、应收天数、存货周转）必须先说明行业口径是否适用；银行、保险、证券不能套用一般工商企业的流动比率与净负债判断。
- 会计恒等式不成立时，先怀疑**单位（元/千元/万元/百万元/亿元）、口径（合并/母公司）、期间（时点/区间）**，再怀疑数据本身。失败反查会给出单变量数量级替换的结果，`ambiguous` 表示多个科目同时错、必须转人工。
- 允许并鼓励"未发现异常"的结论。不要为了填满报告而降低阈值或重复计数。
- 保持零改动：本技能只读事实、产出声称，不修改原始数据，不覆盖既有运行结果。

交付物至少包含：运行 ID、样本与口径、命中的规则与排序、每条的评分分解与证据 ID、反证检索结果、未解问题、传导到的估值参数、以及明确的"未覆盖范围"。
