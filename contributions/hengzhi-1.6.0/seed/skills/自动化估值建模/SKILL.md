# 自动化估值建模（竞赛选题 ④）

## 这个技能解决什么问题

把"已经提取好、已经核验过的财务数据"变成一份**可复现、可追溯、可被质疑**的估值模型。
交付物是**价值区间 + 假设来源表 + 敏感性矩阵**，不是目标价。

竞赛三大考核点在本技能里的具体含义：

| 考核点 | 在本技能里怎么落地 |
| --- | --- |
| **可验证** | 每个驱动变量都写清来自哪一期、哪个科目、哪条公式；无法取到就标注为假设 |
| **可追溯** | `inputs_used` / `assumption_sources` 逐项给出 `period` 与 `evidence_ids` |
| **可复现** | 同一份输入跑两次结果完全一致；所有假设都在 `parameters` 里显式列出，没有隐藏默认值 |

## 三条硬纪律

1. **假设必须有依据。** 收入增速、毛利率、费用率、税率、资本开支率、周转天数、
   净债务一律由已核验数据自动校准；校准不到的才用默认值，且必须**显式标注为假设并说明理由**。
   一个说不出依据的假设，天然不可验证 —— 这是本选题最容易失分的地方。
2. **输出区间，不输出目标价。** 三情景权益价值是"按情景分布的合理价值区间"，
   不是目标价，也不构成投资建议。交付物里必须原样保留这层免责。
3. **压力情景不是手填的悲观数字。** 每一条参数改动都要能回答"是哪个 `rule_id` 让我这么改的"。

## 执行入口

先检查当前环境真实可用的工具，不要凭本技能的描述假定工具存在。

**两个估值入口的分工（先选对工具，再谈方法）**：

| 工具 | 什么时候用 | 关键差异 |
| --- | --- | --- |
| `build_pro_valuation_model` | **默认首选**（A 股口径增强内核） | 逐年驱动预测、三表联动、WACC 与终值**来源标注**、三情景、敏感性、反向 DCF、蒙特卡洛、同行相对估值、`football_field` / `valuation_range` / `per_share_range`；导出**活公式 Excel**（引用单元格而非写死数值，可用 LibreOffice 重算校验）；缺数据返回 `refusals` 补数清单 |
| `build_valuation_model` | 需要三表配平明细、或要用 `read_valuation_model` 分段读取 | 多阶段 FCFF / 金融企业剩余收益；含五项勾稽的三表与 FCFF 交叉验证；压力情景 = 证据驱动传导 + 结构性兜底 |
| `scenario_valuation` | 只需三情景压力测试 | 比上面两个轻，适合快速回答"压力下值多少" |

三者都**复用 `analyze_financial_report` 的 `run_id`** 取事实——不得用待核查研报自证。

`build_pro_valuation_model` 的返回字段怎么读：

- `drivers` 每个驱动变量都带来源标签（财报实算 / 市场输入 / 显式假设），引用时**必须带上标签**。
- `refusals` **非空即表示缺关键数据、模型没有产出可信结果**。此时如实说明缺什么、怎么补，
  **不得用默认值填平**（"不用默认值填平"是本技能的硬纪律）。
- `gates` 是 `valuation_sanity.run_gates` 的体检项，如 `G01_TV_SHARE`（终值占 EV > 75% 告警）、
  `G18_EXIT_CROSS`（Gordon 隐含终年 EV/EBITDA vs 同行，比值应 ∈ [0.67, 1.5]）。`warn` 项必须在报告里解释。
- `no_target_price` 固定返回"不输出目标价，仅输出区间；不构成投资建议"——**这是引擎的硬规则，不得绕过**。
- `scenario_distinctness` 检查三情景是否真的互不相同；三情景给出同一个数不算做了情景分析。

- **本地金融 Agent（FinSleuth）**：严格按顺序调用
  1. `analyze_financial_report(filenames=[...])` → 拿 `run_id`（记为 A）
  2. `forensic_scan(run_id=A, peer={...})` → 拿 `run_id`（记为 F）
  3. `scenario_valuation(run_id=A, forensic_run_id=F)` → 三情景估值

  三个 ID 必须真实串联，不要凭记忆重述上一步结果。若跳过第 2 步，`scenario_valuation`
  会自动取最近一次法证运行；若一次都没跑过，压力情景就退化成基准情景而**看不出异常** ——
  报告的结论会虚假地"稳健"。
- **其他 harness / 需要可复现证据**：在本项目目录用 CLI 一条命令跑完整链路，
  这也是"可复现"考核点最直接的证据（命令原样写进交付物）：

  ```bash
  .venv/bin/python -m server.finance_cli valuation \
      --input 年报.pdf --company 公司名 \
      --overrides '{"comparable_pe":25,"comparable_ev_ebitda":15}' \
      --output 输出目录
  ```

  该命令内部依次执行 `analyze_financial_report` → `forensic_scan` → `scenario_valuation`，
  并把 analysis / forensic / valuation 三个运行的 `run.json` 与 xlsx/md/json 导出
  分别写进 `输出目录/<kind>/<run_id>/`。加 `--no-forensic` 可跳过法证扫描做对照
  （此时压力情景必然退化为基准情景）。加 `--peer '{"gross_margin":[0.5,0.55]}'`
  可传入同行数据。先跑 `--help` 确认选项，以帮助输出为准，不猜测未列出的参数。
- **缺少项目工具**：可以手工搭 DCF，但必须明确写出"以下估值未经项目引擎复算"，
  并说明 FCFF、终值、净债务桥接的具体口径，不要声称用了本技能的三情景框架。

## 模型结构

```
FCFF_t = EBIT_t × (1 − 有效税率) + 折旧摊销_t − 资本开支_t − ΔNWC_t
EBIT_t = 营业收入_t × (毛利率 − 期间费用率)          ← 除首年外
首年 EBIT 额外扣除：营业收入 × impairment_to_revenue（一次性税前减值）
近端两年 FCFF 额外折减：×(1 − near_term_fcff_haircut)
整条现金流折让：×(1 − sustainable_profit_discount)   ← 含终值

EV      = Σ FCFF_t / (1+WACC)^t + TV / (1+WACC)^n
TV      = FCFF_{n+1} / (WACC − g)
权益价值 = EV − 净债务 − 少数股东权益 + 非经营性资产
每股价值 = 权益价值 / 总股本
```

`g >= WACC` 时引擎**拒绝计算并返回 `ok=false`**，不会硬算出一个数。
见到这个警告不要绕过，回去检查假设：永续增长率不可能长期高于折现率。

## 假设校准表（引擎自动做的，报告里要逐项引用）

| 驱动变量 | 来源优先级 | 校准公式 / 依据 |
| --- | --- | --- |
| `revenue_base` | 已核验事实 | 最新一期营业收入，**primary 级证据优先**（主表原文 > 摘要页四舍五入值） |
| `revenue_growth` | 派生 | 近 N 年营业收入复合增速 **与** 最新一期同比**取较低者**，再封顶 20% |
| `gross_margin` | 指标 | `gross_margin` =（营业收入 − 营业成本）/ 营业收入 |
| `opex_ratio` | 派生 | （销售费用 + 管理费用 + 研发费用 + 税金及附加）/ 营业收入 |
| `tax_rate` | 派生 | 所得税费用 / 利润总额，夹在 [0, 50%] |
| `da_to_revenue` | 派生 | `depreciation_total` / 营业收入 |
| `capex_to_revenue` | 派生 | **abs(capex)** / 营业收入 |
| `receivable_days` / `inventory_days` / `payable_days` | 指标 | 引擎已算好的周转天数，不重算 |
| `net_debt` | 派生 | −`net_cash` = 有息负债 −（货币资金 + 长期银行存款） |
| `non_operating_assets` | 事实 | 按公平值计入损益的金融资产等；长期银行存款若已在净债务里净掉就**不得再加** |
| `minority_interest` | 事实 | 少数股东权益（时点值） |
| `shares` | 派生 | 归属于母公司股东的净利润 / 基本每股收益（E2 级近似，须标注） |
| `wacc` / `terminal_growth` / `years` | **假设** | 行业中性值，不是这家公司的；必须显式标注为假设或由 `overrides` 替换 |

## 工作流程

1. **先看数据质量，再看数字。** 读 `data_quality` 与 `degraded_inputs`：
   - `from_company_data` 列出取自公司已核验数据的变量 —— 这些可以直接写进假设表。
   - `from_default_assumptions` 列出沿用默认值的变量 —— 这些**必须在报告里标注为假设**。
   - `degraded_inputs` 逐项说明影响（例如"净债务沿用默认假设"）。
   - `missing_inputs` 是硬性缺口；含 `revenue_base` 时 `ok=false`，
     **不要用默认值偷偷填平**，先回去解决提取问题。
2. **核对隐含 EBIT 自检。** `calibration_checks` 里的 `ebit_calibration` 把模型隐含的
   `revenue × (毛利率 − 期间费用率)` 与报表口径的 `利润总额 + 财务费用` 直接对比。
   `status=attention`（差异 > 15%）说明期间费用率可能遗漏了重要的损益项目，
   必须在报告里说明，不得当作没看见。
3. **看基准情景是否合理。** 把 `scenarios.base.parameters` 与公司实际历史对比，
   并把 `implied_ev_ebitda` / `implied_pe` 与行业常识区间对照：
   - 隐含 EV/EBITDA 落在 [3, 40] 之外、或隐含 P/E 落在 [5, 60] 之外，
     引擎会告警 —— 先怀疑**输入错了**，而不是"公司特别便宜/贵"。
4. **核对压力情景真的构成压力。** 读 `stress_diagnostic`：
   - `adjustment_count` 与 `adjustments` 列出每条传导（`from → to`）。
   - `insufficient = true` 表示压力情景与基准情景差异不足 2%，
     **本次压力测试没有构成实质压力**。报告中必须写明这一点，
     不得把该结果当作"风险已充分量化"。
   - `unmatched_risks` 列出"没定义传导路径"或"参数缺失"的规则，
     必须在交付物里列为**待补假设**，不能静默丢掉。
5. **读敏感性矩阵。** `sensitivity_base` 是 WACC × 永续增长率 的二维矩阵（默认 ±2 步）。
   看区间宽度，不看单点。终值占企业价值 > 75% 时引擎会警告 ——
   此时结论几乎全由永续假设决定，必须把矩阵放进交付物，不能只给一个数。
6. **做双方法交叉验证（可选但强烈建议）。** 在 `overrides` 里给
   `comparable_ev_ebitda` 与 `comparable_pe`，工具会反推隐含权益价值，
   与 DCF 结果并列。**可比倍数必须由使用者提供并说明可比组选取依据**，
   工具不会替你编一个同业倍数。
7. **交付。** 输出三情景权益价值区间 + 每股价值区间 + 每情景关键驱动变量表 +
   假设来源表 + 压力传导来源表 + 敏感性矩阵 + 数据质量声明 + 不确定性说明。

## 常见错误（全部实测踩过，逐条对照）

1. **期间费用率用「毛利率 − 净利率」反推。** 这个口径下 `EBIT = 营业收入 × 净利率`，
   EBIT 里已经扣过一次所得税，再乘 (1 − 税率) 就是**重复扣税**。
   实测把某公司 EBIT 从 209.8 亿元压到 158.7 亿元，低估 24%。
   → 必须用真实费用科目。引擎会在缺明细时降级并告警，见到告警要人工核对。
2. **资本开支率取到了负值。** 港股/IFRS 现金流量表的"购买物业厂房及设备"是投资流出、
   原文以括号列报、入库后带负号。直接除会得到负的资本开支率，FCFF 被系统性高估。
   → 一律取 `abs(capex)`。实测某公司资本开支率真值 12.33%，默认值 6% 差一倍。
3. **净债务只取「短期借款 − 货币资金」。** 会漏掉：① 租赁负债（有息负债，港股常见）；
   ② 长期银行存款（类现金）。实测某公司净债务因此从 −177.73 亿元算成 −67.88 亿元，
   **权益价值等额低估 109.85 亿元**。
   → 必须复用引擎已算好的 `interest_bearing_debt` / `cash_and_deposits` / `net_cash` 指标，
   它们内含"总括行优先、明细回退 + 金额去重"的取值阶梯。估值侧不要自己再拼一遍。
4. **长期银行存款既在净债务里净掉、又加进非经营性资产。** 重复计一次 110 亿元级别的资产。
   → 二者只能选一处，引擎按"是否已净掉"自动判断。
5. **税率硬编码 15%。** 应按 `所得税费用 / 利润总额` 校准；实测某公司有效税率 24.14%。
6. **收入增速硬编码 8%、毛利率硬编码 30%。** 与被估值公司实际（15.34% / 60.53%）相差一倍。
   → 引擎从历史数据校准，增速取"复合增速与最新同比的较低者"并封顶，
   避免把单一年份的高增长外推成五年期假设。
7. **压力情景对净现金公司失效。** 某公司 `net_debt = −177.73 亿元`，
   债务风险规则若以净值作规模基准，调整量会变成 +0.03 **元**，
   三情景数值看起来一模一样，而报告上看不出任何异常。
   → 引擎改用有息负债总额作基准，并新增 `stress_diagnostic.insufficient` 显式报出。
8. **用待核验数据跑估值。** 三表不平、单位错位、口径未统一时，**先修数据再估值**。
   用待核验数据跑出来的区间没有意义。
9. **把摘要页数字当主表数字。** 同一科目在摘要页是四舍五入值（实测差 90,000 元），
   会让"报告内可复算"的校验平白失败。引擎按证据层级优先取主表。
10. **三项周转天数直接相加再乘收入。** 三者的分母并不相同：
    应收天数用**营业收入**作分母，存货与应付天数用**营业成本**作分母。
    直接相加等于默认存货与应付也用收入作分母，会把营运资本占用放大
    1/(1 − 毛利率) 倍 —— 实测某公司真实净营运资本占收入 8.41% 被算成 19.69%，
    ΔNWC 虚增一倍以上，FCFF 与估值被系统性压低。
    → 引擎已按 `应收天数 +（存货天数 − 应付天数）×（1 − 毛利率）` 折算到收入口径，
    报告里引用营运资本假设时请引用 `nwc_days_revenue_basis` / `nwc_to_revenue`，
    不要引用三项天数的简单相加。

## 交付前自检清单

- [ ] `missing_inputs` 为空；若有 `revenue_base`，已回去解决提取问题而不是填默认值
- [ ] `data_quality.from_default_assumptions` 里的每一项都已在报告中标注为"假设"并写了理由
- [ ] `assumption_sources` 逐项引用，每个驱动变量都能回答"从哪来"
- [ ] `ebit_calibration` 为 `pass`，或已说明差异原因
- [ ] 隐含 EV/EBITDA 与 P/E 落在常识区间内，或有明确解释
- [ ] `stress_diagnostic` 已读；`insufficient=true` 时报告已写明"未构成实质压力"
- [ ] `unmatched_risks` 已全部列为待补假设
- [ ] 敏感性矩阵已放进交付物；终值占比已披露
- [ ] 三情景区间 + 每股价值区间齐备，且保留了"不是目标价"的免责
- [ ] 每个派生值都能用报告里已有的数字复算出来

## 输出纪律

- **输出区间，不输出目标价。** 保留免责声明原文。
- 每个关键数字都要能回答"参数从哪来"：历史值（哪一期）、同行值（哪几家的中位数）、
  还是规则推导（哪个 `rule_id`）。没有来源的就是假设，要显式标注。
- 金额一律用 `Decimal`，比例用分数（0.2 = 20%）。前端展示再做百分比格式化，
  不要在计算层四舍五入。
- **不修改原始事实、不覆盖既有运行结果。** 需要改假设就用 `overrides` 显式覆盖，
  并在交付物里说明改了什么、为什么。
- 三表不平、单位错位、口径未统一时，**先修数据再估值**。

交付物至少包含：运行 ID、输入事实清单（含期间与口径）、假设来源表
（区分"取自公司数据"与"默认假设"）、三情景驱动变量对照表、压力传导来源表
（含未匹配规则与压力有效性结论）、权益价值区间、每股价值区间、敏感性矩阵、
终值占比、数据质量声明，以及明确的"未覆盖范围"与"未扣项/未加回项"。
