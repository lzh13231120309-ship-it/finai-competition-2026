# 证据与字段契约

这是候选记录的设计指南。项目工具实际返回的 schema、字段名称、ID 和校验结果是执行依据；不要为让输出符合示例而重命名或编造系统证据 ID。

## 事实的最小上下文

| 信息 | 要求 |
|---|---|
| 主体/指标 | 公司名称、科目或事件字段；必要时含证券代码、原始科目名 |
| 值 | 原文值 `raw_value`；确定后给标准值，无法确定用 null |
| 单位/币种 | 原文单位、币种；归一化数值需明确换算公式 |
| 期间 | 原文日期、标准期间、余额时点或发生额区间；不能只写“2025” |
| 范围 | 合并、母公司、集团、子公司或未知；不同范围不得拼成一组 |
| 证据 | 原文件、真实 evidence_ids、页/工作表、表格/行列、短原文及定位跨度（工具提供时） |
| 状态 | 已抽取、待核验、冲突、缺失等；具体理由比无依据的置信度数字更有用 |

保留解析器产生的 evidence ID 与 span，引用同一来源时直接复用。Excel 引用工作表/单元格，CSV 引用行号；没有页码的文件不能虚构页码。模型候选可以附 `evidence_ids` 和 `source_quote`，但不得自称是解析器生成的事实。

## 自定义 records

每条记录建议使用 `fields` 对象，每个字段必须采用 `{value, evidence_ids, raw_value?}` 格式。证据必须附在具体字段上，不能只在整条记录上附一次。可以在 `fields` 外附事件类型和备注，避免将记录元数据误当待验证字段。`required_fields` 使用 `fields` 中的实际字段名；缺失时保留 null 并标理由，不能通过删字段或伪造值让检查通过。

结构示意如下，尖括号内容必须替换成 inspect 返回的实际原文和 ID，不可作为候选值提交：

```json
{
  "records": [
    {
      "fields": {
        "出质人": {"value": "<原文中的出质人>", "evidence_ids": ["<实际证据ID>"]},
        "到期日": {"value": null, "evidence_ids": []}
      },
      "review_notes": ["原文未披露到期日"]
    }
  ],
  "required_fields": ["出质人", "到期日"]
}
```

当前验证器检查提交字段的格式、必填项、证据是否存在，以及原值是否在所引证据中出现；匹配会忽略空白、英文/中文逗号和大小写。它不证明主体关系、事实完整性或字段语义。如果 `value` 与 `raw_value` 不同，即使原值能匹配，转换仍列入待核验。比如原文“1.2亿元”转换成数字 120000000，需要另行明确单位并核对，不能将字符串匹配当作完成换算验证。

验证返回 `run_id`、逐字段状态和 `review_queue`，可用这个实际 run_id 导出结构化记录与核验结果。报告需保留 `grounded`、`missing`、`needs_review` 的区别。

下面是字段选型，不是实际抽取结果：

| 场景 | 推荐字段 | 容易误读的边界 |
|---|---|---|
| 股权质押 | 证券代码、出质人、质权人、质押股数、占其持股比例、占公司总股本比例、质押/解除日期、到期日 | 本次/累计质押；两种比例分母；股份与金额；解除与新增 |
| 中标/合同 | 公司、项目、招标方/客户、中标日期、含税/不含税金额、币种、合同期、联合体角色、履约条件 | 预中标与正式中标；框架上限与确定金额；公司份额与联合体总额；订单与收入 |
| 股权变动 | 标的/发行人、交易方、交易方式、变动前后股数与比例、价格/对价、公告/交割日期、审批条件 | 意向与交割；直接/间接持股；比例分母变化；增资与老股转让 |
| 财务科目 | 公司、科目、期间、报表范围、原数、单位、币种、重述状态 | 本期/比较期；累计/单季；合并/母公司；表头单位跨页 |

检查候选时逐个回答：此字段原文是否存在？值是否逐字/逐数匹配？单位和日期是否正确？引用是否确实支持该值？有无遗漏其他事件？验证器未覆盖的检查，在交付说明里标明。

## 冲突与 OCR

例如同一页识别成“1,258.0”与“12,580”时，不按规模常识选一个。回看原表或更清晰图；无法消歧时留两种候选及来源，将标准值置空。跨页表格先检查续表单位和列标题，不能把页眉、合计、注释并入科目。

低置信度是复核优先级，不是自动正确率。没有人工复核或明确验证结果，不能写“数据已审计”“全部准确”或给出抽取成功率。
