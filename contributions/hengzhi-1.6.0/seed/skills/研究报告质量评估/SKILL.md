# 研究报告质量评估（竞赛选题 ⑦）

把"这篇研报写得好不好"从**主观印象**变成**可复算的分数**：
每个子指标都指向报告里具体的句子，评委能逐条回原文核对。

## 一、必须先说清的三件事

1. **这是项目内部量表，不是竞赛官方评分。** 引擎固定返回 `scale_note`，交付物里必须原样声明。
   把内部量表说成"官方评分"是硬伤。
2. **总分必须配覆盖率。** 只报"总分 3.8"而不给 `coverage`，
   "覆盖率 40% 但分很高"会被误读成"报告很好"。**引用总分必须同时给 `coverage`。**
3. **排序必须配长度基线。** 实测"仅按字数排序"就能在 31 对盲评标签上拿到 87.1%。
   不给基线的"排序准确率 96.8%"没有说服力。**报排序准确率必须一并报长度基线。**

## 二、评分结构

**5 个维度**（权重是内部建议权重，不来自任何官方量表）：

| 维度 | 权重 | 评什么 |
| --- | --- | --- |
| `logic` 论证逻辑 | 0.30 | 结构完整性、因果论证、反证条件、事实/推论/观点区分、估值方法与假设、情景 |
| `evidence` 证据支撑 | 0.25 | 来源标注率、数字密度、图表来源、观点—证据对应 |
| `fact` 事实准确 | 0.20 | 带单位/期间/口径的数字占比、内部算术与公式复算 |
| `risk` 风险披露 | 0.15 | 风险条数与具体性、是否量化、是否与盈利预测联动、不确定性披露、合规措辞 |
| `action` 可操作性 | 0.10 | 跟踪指标、催化剂时点、待解问题、触发条件、决策建议 |

**28 个子指标**（每个 0–5 分，带命中行号与规则 ID）：

- 结构：`struct.completeness`
- 数据：`data.density`、`data.qualified`（同时带单位/期间/口径的数字占比）、`data.source_rate`、`data.figure_source`
- 论证：`arg.claim_evidence`（观点—证据对应）、`arg.causal`、`arg.counter`（反证）、`arg.epistemic`
- 估值：`val.method`、`val.assumptions`、`val.scenario`、`val.range`
- 风险：`risk.count`、`risk.specific`、`risk.quantified`、`risk.link`、`risk.uncertainty`
- 行动：`act.tracking`、`act.catalyst_timing`、`act.open_questions`、`act.trigger`、`act.decision`
- 合规：`comp.absolute`（绝对化措辞）、`comp.rumor`、`comp.disclaimer`
- 内部一致：`consist.arith`、`consist.formula`

**加权子指标**（权重 > 1.0）：`arg.claim_evidence` 1.5、`data.source_rate` 1.5、`consist.arith` 1.5、
`val.method` 1.2、`val.range` 1.2、`consist.formula` 1.2、`risk.specific` 1.2；其余为 1.0。

## 三、`None` 不是 0 分（最容易讲错的一点）

**不适用的子指标返回 `None`，从加权均值中剔除，不按 0 分算。**
例：报告里没有图表、没有显式算式，那几项就不计分——**`None` 表示"该报告本来没有这类内容"，
不代表写得差**。总分只在已评部分内可比，所以必须报 `coverage`。

`review_queue` 里两类条目要分开读：

- `kind='low_sub'`：**低于 2.5 分的子指标**，附 `why` 与 `evidence`（命中原文），是真正要改的地方。
- `kind='not_applicable'`：该报告本来没有这类内容，**不是低分**。

## 四、实测指标（2026-10-12 复测）

语料：54 份东财真实研报 + **31 对人工盲评偏好标签**（标签由作者在未看评分结果前通读后配对，带主观性）。

| 子集 | 对数 | 本模型 | 字数基线 |
| --- | --- | --- | --- |
| 全部 | 31 | 96.8%（30/31） | 87.1% |
| `depth`（深度差异） | 17 | 100% | 100% |
| `same_tier`（同档次细比） | 8 | 87.5%（7/8） | **100%** |
| **`anti_length`（长度与质量反向）** | 4 | **100%** | **0%** |
| `decision_support` | 2 | 100% | 100% |

**怎么读这组数（引用时必须照此口径）**：

- `depth` 子集上本模型与字数基线**都是 100%**——说明"深度差异"光靠篇幅就能判对，
  该子集**不构成证据**，不能拿来证明模型有效。
- 真正的证据是 `anti_length`：长度与质量**反向**时，字数基线 0%、本模型 100%。
- **`same_tier` 上本模型 87.5% 反而低于字数基线 100%**，这是**已知短板**，必须如实写出来。
  同档次细比场景下，篇幅仍是最强的单一信号。

复现命令：`.venv/bin/python scripts/eval_quality_pairs.py`

## 五、调用方式

`assess_report_quality(filename | report_path | text)`：

- 交付前调用**一次**；
- **多份报告排序**时对每份各调一次，再比 `total`（同时比 `coverage`——覆盖率差太多的两份不可直接比）。

返回字段：`total`、`coverage`、`dimensions`、`subs`（28 项，含 `score`/`id`/`dim`/命中证据）、
`review_queue`、`consistency`、`scale_note`、`coverage_note`、`run_id`。

## 六、机器评不了什么（必须交人工）

机器只评**可观察**的东西：来源标注率、数字密度、观点—证据对应、反证条件、绝对化措辞、内部一致。
以下仍属**人工评审**范围，**不得声称已自动完成**：

- 行业适用性（这个估值方法适不适合这个行业）
- 因果链的实质成立性（连接词出现了 ≠ 因果成立）
- 利益冲突与独立性判断
- 事后信息（用了报告日之后才公布的数据）

交付物里要明确写"以下维度未经自动评估，待人工评审"。

## 七、输出纪律

- 引用总分必须同时给 `coverage`。
- 必须声明"项目内部量表，不是竞赛官方评分"。
- 多份排序要一并报"仅按字数的长度基线"。
- 未评项不是 0 分，不得自造补全后的总分或排名。
- `review_queue` 的 `low_sub` 要连 `why` 与 `evidence` 一起给出。
- 不把章节标题和免责声明的出现等同于经济逻辑严谨。

## 八、交付前自检清单

- [ ] 总分旁边给了 `coverage`
- [ ] 写明"项目内部量表，不是竞赛官方评分"
- [ ] 说明 `None` / `not_applicable` 不等于 0 分
- [ ] 多份排序时给了长度基线
- [ ] `review_queue` 的每条都带命中原文，能回原文核对
- [ ] 明确列出未自动评估、待人工评审的维度
- [ ] 没有自造补全后的总分或排名
