# 上市公司财务报告分析

用可追溯事实回答用户的财务问题。把源数据、公式、财务解释和待核验事项分开；结论不能超出上传资料覆盖的公司、期间与范围。

## 执行入口

先检查真实可用工具：

- **本地金融 Agent**：用 `inspect_document` 检查文件、来源和表头；用 `extract_financial_data(filename, company?, period?, scope?)` 查看事实及复核队列；用 `analyze_financial_report(filenames?, company?, period?, scope?)` 生成确定性分析产物。多文件比较传实际上传文件名；不指定文件时先明确当前任务中哪些附件会被采用。按返回的 `run_id` 调用 `export_financial_report`。
- **其他 harness**：在用户指定的本项目目录运行 `python -m server.finance_cli --help` 和所需子命令的 `--help`，有 `.venv/bin/python` 时优先使用。`inspect`、`extract`、`analyze` 用 `--input` 传一个或多个本地文件；`export` 用 `--run` 传已生成的运行 JSON。以帮助输出为准，不猜测 flags、路径或工具名。
- **缺少项目工具**：可从可读取文件制作有证据的分析，使用实际可用的计算工具复算；明确哪些事实尚未验证、哪些计算是此次补算。工具或文件读不到时，不模拟执行结果、`run_id` 或下载链接。

## 从数据到结论

1. **确认样本与口径**：列出公司、行业、报告期、报表范围、币种、单位、审计/未经审计、重述状态，以及覆盖的三张报表。资料不完整仍可做已获授权的部分分析，说明结论的覆盖范围。
2. **核对事实**：检查单位、表头、比较期与科目证据。资产负债表是时点数据；利润和现金流是区间数据。比较优先用同一最新报告内的本期/重述比较期，保留原报告版本；禁止混用母公司与合并数据。
3. **确定性计算**：优先采用 `analyze_financial_report` 返回的事实、公式、操作数和结果。阅读 [指标及核验规则](references/metric-rules.md)，检查适用性、缺失和分母。结果应引用输入事实的证据 ID。补算指标时附公式、实际操作数及来源，标为补算，不伪称工具产物。
4. **财务解释**：围绕用户关心的问题写盈利、现金转化、负债结构、周转与趋势。将“报表显示的变化”与“可能的经营原因”分别写清。原因需管理层讨论/附注支持；没有支持时列待验证假设，不补写业务故事。
5. **异常信号复核**：对利润与经营现金流背离、应收/存货变化、资金限制、勾稽差异等查看相关附注和其他解释。工具阈值是筛查启发式，不是监管标准。数字差异可来自舍入、口径、汇率或解析错误；按证据评价，不把财务信号写成造假结论。
6. **交付并导出**：使用用户要的格式导出实际生成的 `run_id`，并在答复附产物链接、关键结论、依据和未核验项。不能删除待核验事项后宣称报告完成核验。

## 输出的证据层次

- **披露事实**：原文数字、表格/页码、币种、单位、期间、范围及证据 ID。
- **计算结果**：公式、输入事实、计算口径；不可计算项给具体原因，不能输出 0 或强行评分。
- **分析判断**：解释与不确定性；注明是否有附注佐证。
- **待核验事项**：缺表、矛盾、OCR 歧义、未披露数据、口径不匹配与复核建议。

报告篇幅按用户需求调整。不强制综合评分、投资评级、目标价或“健康/不健康”标签。未提供股价、行业对照和预测假设时，不凭历史报表推导估值或投资收益。

## 严格边界

- 只使用实际可读证据。解析置信度是启发式提示，不是经过校准的概率或正确率。
- 银行、保险、证券等金融企业不能直接套一般工商企业的流动比率、存货周转、毛利率或净负债判断。若核心工具未提供行业口径，指出不适用，保留可证实的披露分析。
- 经营现金流、货币资金、现金及现金等价物、受限资金分别处理，不能只凭名称视为同一项。
- 无论程序是否给出数值，分母异常、期间错配或来源待核验的结果都不能用于确定性结论。
- 对 fraud、舞弊、虚假披露等定性，必须区分已披露调查/处罚事实和自身筛查信号。该工作流提供复核线索，不作无证据指控。
- 原文件和原事实保留；更正和人工确认作为新的版本/注释记录，不静默改写来源。
