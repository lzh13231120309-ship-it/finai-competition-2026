# 港式 / H 股 / 英文报表识别要点

## 为什么要单独一层

真实材料里很大一部分是**繁体 + 英文双语**（H 股年报、红筹、B 股、外企），
而且往往按 **IFRS / HKFRS** 列报，科目名与 A 股准则差异很大。

只认简体中文的词典在这些材料上会提取到 **0 条事实**——不是"算错了"，
而是"根本没认出来"，而且**失败是静默的**，最容易被误判成"模型能力不行"。

实测样本：农夫山泉（9633.HK）2025 年报 —— 扫描版、繁體中文/English 对照、
人民币千元列报。旧词典命中 **0 条**。

---

## 一、繁简转换：必须用全集，不能手写小表

曾经的做法是手写一张 179 字的繁简表，理由是"财务文本用字有限，不值得全集"。
**事实证伪了它**：漏掉「貿」之后，H 股年报里最常见的「貿易應收款項」
整条科目**静默消失**——提取结果少一项，不报任何错，是最难发现的一类缺陷。

现在的做法：内置 **OpenCC TSCharacters 全量表（3109 字对）**，
纯数据、零运行时依赖（应用是离线打包的，不能随便加包），再加一个**领域覆盖层**：

| 覆盖 | 原因 |
| --- | --- |
| `帳 → 账` | 港式年报写「帳目／帳面值／應收帳款」，而大陆简体统一用「账」。OpenCC 字表给的是「帳 → 帐」（对应帐篷的帐），在这个语境下是错的。 |

**经验**：凡是"用语域有限"为理由手写映射表的做法，都要预期它会漏。
宁可带一份全量表，也不要靠枚举。

## 二、双语单元格必须先切分

真实双语单元格长这样：`貿易應收款項 Trade receivables` —— 中英文挤在同一格。

- 整串既不是中文科目也不是英文科目，直接匹配必然失败。
- **中英之间的空白必须一起吃掉**：边界处是**空格**而不是字母，
  用"严格相邻"的正则断言（`(?<=[\u4e00-\u9fff])(?=[A-Za-z])`）会**一个都切不开**。
  正确写法要在中间允许 `\s*`。
- 策略：**先试整串，再按中英边界切开分别试。**

## 三、英文 / HKFRS 科目别名（易错对照）

| 标准代码 | 常见英文写法 |
| --- | --- |
| `revenue` | Revenue、**Turnover**、Total revenue、Operating revenue、Sales、Revenue from operations |
| `cost_of_revenue` | Cost of sales、Cost of revenue、Cost of goods sold、Cost of inventories sold |
| `gross_profit` | Gross profit |
| `net_profit` | Net profit、**Profit for the year**、Profit for the period、Net income |
| `parent_net_profit` | Profit attributable to owners of the Company / to owners of the parent / to shareholders of the Company / to equity holders of the Company |
| `nonrecurring_adj_parent_profit` | Profit attributable to owners of the Company **excluding non-recurring items**、Recurring net profit attributable to shareholders |

易错点：

- **`Turnover` = 营业收入**，不是"周转率"。港式报表极常用。
- **`Profit for the year` = 净利润**（含少数股东），不等于归母净利润。
  归母必须看到 `attributable to owners of the Company` 这类限定。
- 亏损年份写 `Loss for the year`，符号为负，不要把 `Loss` 当科目名找不到。
- IFRS 报表常**直接列「毛利」而不单列营业成本**。
  此时用 `gross_margin = gross_profit / revenue` 倒算，而不是找 `cost_of_revenue`。

## 四、报表类型识别

| 报表 | 中文 | 繁中/港式 | 英文 |
| --- | --- | --- | --- |
| 资产负债表 | 资产负债表 | **財務狀況表** | Balance Sheet、**Statement of Financial Position** |
| 利润表 | 利润表、综合收益表 | **損益表、收益表、損益及其他全面收益** | Income Statement、**Statement of Profit or Loss**、Comprehensive Income |
| 现金流量表 | 现金流量表 | 現金流量表 | Cash Flow Statement、statement of cash flows |
| 权益变动表 | 权益变动表 | 權益變動表 | Changes in Equity |
| 附注 | 财务报表附注 | 財務報表附註 | Notes to the Financial Statements |

**「財務狀況表」= 资产负债表**、「損益表」= 利润表，是最常见的两个港式陷阱。

## 五、英文单位与日期

单位模式（含英制）：

| 写法 | 判定 |
| --- | --- |
| `RMB'000` / `RMB 000` / `RMB in thousands` | CNY，千元 |
| `RMB million` / `RMB in million` | CNY，百万元 |
| `HK$'000` / `HKD in thousands` | HKD，千港元 |
| `HK$ million` | HKD，百万港元 |
| `US$'000` / `USD million` | USD，千美元 / 百万美元 |

**`(?<!编制)` 是必须的**：`编制单位：元通有限公司` 里"单位：元"会被正则
误判成"单位：元"，于是把一张元表判成"元表"、或把万元表判成元表。这是踩过的坑。

日期：`31 December 2025`、`year ended 31 December 2025`、`FY2025` 都要能识别。

- 是否构成"一段期间"要由**期间词**决定，而不是由日期本身决定：
  出现 `year ended` / `for the year` 才能判 annual 或 ytd。
- 两个日期中若前一个是 `1 January` 且早于后者，是区间；
  否则是时点（资产负债表日）。
- 英文日期的月份缩写（Jan / Feb / … / Dec）与 `st / nd / rd / th` 序数后缀都要吃掉。

## 六、币种兜底：主导币种

单一年度报告通篇只用一个记账本位币，但某些附注页不会重复「人民币千元」，
逐表识别会留下一堆 `unknown`。用全篇出现频次的主导币种兜底更稳。

**纪律**：只有主导币种的出现次数**至少是次席的 3 倍**才下结论，否则返回 `None`
（宁可 unknown，不要猜）。出现两种以上币种并列时判 unknown。

## 七、跨行折断的科目名

港式 / H 股报表会把一个科目名折成 **2–3 行**显示，例如：

```
貿易應收款項
Trade receivables
```

处理方式：

1. 取该行的**碎片单元格**（文字片段）。
2. 与**当前正在追踪的科目**（上一行已识别的科目）拼接后试匹配。
3. 按 **3 段 → 2 段 → 1 段**的宽度依次试，先长后短。
4. 拼接成功则归属到该科目；失败则视为普通文本行，不产出事实。

同一行若有多个碎片单元格，需先判定哪个是"科目名所在列"，
避免把数值列的文本混进科目名。

## 八、OCR 表格几何重建

扫描版年报的表格没有结构信息，只有一堆带坐标的文本框。重建要点：

- **按 y 坐标聚视觉行**：同一视觉行的文本框 y 中心落在同一簇。
- **按 x 坐标聚列**：列边界由跨行稳定的 x 间隔推出。
- **去重同段文字的重叠检测框**：OCR 常对同一段文字同时给出**宽框（整行）**
  与**紧框（单词）**两个检测结果。若不去重，整列数据会被数字护栏判定为
  噪声或错位，导致整表失效。（实测踩过。）

## 九、来源分级：三档，摘要页不得越权

同一个「期间 + 口径 + 科目」可能在多张表里各有一个值，必须分级后才能裁决冲突。
共三档，可靠度由高到低：

| 档位 | 判定条件 | 典型情形 | 精度 |
|---|---|---|---|
| `primary` | 表格有框线（`pdfplumber` 等方法），或来自 xlsx/docx 等结构化文件 | 四大报表主表、带框线的附注表 | 与披露一致（千元或元） |
| `summary` | 表格所在页是「財務摘要 / 主要財務數據 / 五年財務摘要 / FINANCIAL HIGHLIGHTS」 | 五年摘要页 | 按百万元列报并**四舍五入** |
| `inferred` | 按文字坐标推断出来的表（`spatial-*` 方法），列边界由 x 位置反推 | 无框线的报表页、附注明细 | 行列可能配错，靠勾稽把关 |

裁决规则：

- **基准档永不被降级**：只有低档在超出舍入量子容差时才被降级，高档不动。
- 差异在舍入量子容差内视为**一致**，两边都保留为已核验事实（下游按档位取用）。
- 若把坐标推断表与主表当同级，同一科目两个值会互判冲突、**双双降级**。
  实测启用坐标表后已核验事实反而从 137 掉到 108，就是因为最精确的主表数据
  被最粗的坐标表拖下水。
- 摘要页与主表的差异**不得**用相对百分比判断。摘要按百万四舍五入，
  主表是千元：2024 年营业收入摘要 42,896,000,000 元 vs 主表 42,895,992,000 元，
  差 8,000 元 —— 在百万级量子内，是同一个数，不是冲突。

### 9.1 几何重建表为什么归 `primary`

几何重建表（`method = ocr_row_rebuild`）是抢救回来的：原表在 `pdfplumber` 里
只剩单列（科目名列整个丢了），用页面文本块的 y 聚行、x 聚列还原。
它**有原表的 bbox 做约束**，且每个单元格仍带原始 OCR 的 `evidence_id`，
证据链不断；可靠性高于自由扫描整页的 `spatial-*`。
判据里明确记在事实的 `source.rebuilt_table` 上，可回溯。

## 十、现金流量表的「变动行」不是余额

港式/IFRS 现金流量表的「調整項」与「營運資金變動」区会重复使用资产负债表科目名：

```
貿易應付款項及應付票據 |  Increase/(decrease) in trade and bills payables  |  154,836
增加╱（減少）
```

这一行的 154,836 是**本期变动额**，不是期末余额。若不拦，它会与资产负债表上的
真实余额（1,654,233）构成 `duplicate_conflict`，把**正确的余额**一起降级为
`needs_review` —— 于是应付账款周转、现金循环周期、应付占款分析整块失效，
而报告只显示"该科目存在冲突值"，看不出是变动额混进来了。

判据与护栏：

- 目标科目属于资产负债表类（`BALANCE_CODES`）；
- **整行**文本命中变动措辞：`增加 / 减少 / 淨增 / 淨減 / 變動額 / 變動淨額 / 增减`，
  或英文 `Increase / Decrease / Change(s) in / Net movement / Movement in`；
- 表类型为 `cash_flow` / `equity_changes` / 未判定。

两点必须注意：

1. 判据要用**整行**文本，不能只用科目那一格的文本。港式排版把中文补充说明
   折到下一行、英文措辞放在另一列，只看科目格会漏判（实测踩过）。
2. **不能**用裸的「变动」二字去匹配。A 股科目
   「以公允价值计量且其变动计入当期损益的金融资产」里就有"变动"，
   而它本身是资产负债表科目，误伤后整条公允价值资产会消失。

跳过的行会在 `warnings` 里逐表列出，便于人工核对是否漏掉了真正的余额行。

## 十一、同一张表里折旧拆成两行时不要合并

港式现金流量表的「調整項」区把折旧拆成：

```
物業、廠房及設備折舊   3,213,368
使用權資產折舊           160,179
```

两行都映射到 `depreciation` 会构成 `duplicate_conflict`，**两条一起**被降级，
现金流量表分析连折旧都拿不到。它们本来就是两个科目，分开登记才如实：
`depreciation` 与 `depreciation_rou_assets`。

同类问题在处理任何"同一科目在一张表里出现多次"时都要先问：
这是**冲突**，还是**明细拆分**？拆分要各给一个代码。

### 12.1 单复数与"多一个词"

别名匹配是**归一化后的精确匹配**，差一个词就不认：

| 报表写法 | 词典里容易写错的形式 | 后果 |
|---|---|---|
| Trade and bills **payables** | `Trade payables and bills payable`（单数） | 整行应付账款漏认 |
| Purchases of **items of** property, plant and equipment | `Purchases of property, plant and equipment` | 整块资本开支漏认，FCFF 与资本开支规则同时失明 |
| 購買物業、廠房及設備**項目** | 「購買物業、廠房及設備」 | 同上 |

新增科目只要写进英文或港式中文别名表就应当生效 ——
词典合并取**并集**而不是只遍历主词典的键；只遍历主词典时，
写在另外两张表里的新代码不会建键、被静默丢弃，
表现是"词典里明明有词条，查询却返回 `None`"，极难排查。

### 12.2 语义错配比漏认更危险

- `Cash generated from operations` / 「經營所得現金」是**税前息前的
  经营活动所得现金**，**不是**"销售商品、提供劳务收到的现金"。
  放进 `cash_from_sales` 会让收现比 = 经营所得现金 / 营业收入（实测约 0.49），
  触发收现质量规则误报。正确别名是 `Cash receipts from customers` /
  `Receipts from customers`。
- 「應付稅項」（负债，时点值）与「稅項」（利润表的所得税费用，区间值）
  一字之差、期间类型相反，必须分开登记。

## 十三、请求公司与披露公司的主体识别

用户输入的公司在名称上几乎不可能与年报封面一字不差。港股年报的典型封面是：

```
农夫山泉
農夫山泉股份有限公司
NONGFU SPRING CO.， LTD.
```

判定"是不是同一家"必须按**归一化后的核心名**比对：

1. **繁简归一**（内置全量表，不要用部分字表 —— 实测 179 字表会漏「貿」）。
2. 去掉标点与空白。
3. **剥掉法定主体后缀**（最多两轮，因为后缀会叠加）：
   `股份有限公司 / 有限责任公司 / 有限公司 / 股份公司 / 集团 / 控股 / 公司 /
    Company Limited / Co., Ltd. / Ltd. / Limited / Incorporated / Inc. /
    Corporation / Corp. / Company / Holdings / Group / PLC / AG / SE`。
4. 拉丁字母转小写。
5. 判据是**核心名互相包含**，不是字符串相等。

### 13.1 判错方向的代价不对称

- 误判为"同一家"：只是少一条提示。
- 误判为"不同家"：**整份报告的全部事实**被打成 `needs_review`，
  下游全部拒收，**一个指标都算不出来**。

实测踩过：用户输入「农夫山泉」、封面是「農夫山泉股份有限公司」，
172 条事实全灭，报告只会说"部分数值待核对"。所以：

- 「发行人不止一个」要**按核心名去重后再数**。封面常常中英文并列、
  或同时出现简称与全称，那是同一家公司的两种写法，不是身份冲突。
- **跨文字系统**（一方全中文、一方全拉丁）无法比对时**不武断否证** ——
  系统拿不到「農夫山泉 = NONGFU SPRING」这种对应关系。
  这种情形保留披露主体名作为事实的来源身份，交人工核对。
- 「本公司 / 该集团 / 母公司 / 子公司」这类指代词也满足"以公司结尾"，
  必须排除出主体名 —— 混进去会让"发行人不止一个"误触发。
