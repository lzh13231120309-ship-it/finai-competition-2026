# 证据分级（E1–E5）与引用规则

竞赛方案对"结论从哪来"有强制要求。每一条进入报告的关键判断都必须绑定
`SourceSpan`、`MetricValue`、`Formula`、`ModelRun` 四类可追溯对象。

---

## 一、五级证据定义

| 等级 | 定义 | 报告中的使用方式 |
| --- | --- | --- |
| **E1** | 法定披露原文或交易所文件中的明确数字与陈述 | **可直接支撑事实** |
| **E2** | 从 E1 按公开公式计算且通过勾稽的数据 | 支撑**计算结果** |
| **E3** | 多个 E1 或 E2 共同支持的模型推断 | **必须展示推理和反证** |
| **E4** | 新闻、互动问答或行业二手材料 | **只作线索或补充** |
| **E5** | 模型建议但无外部证据 | **不得进入最终结论**，只进入待核验列表 |

判据要点：

- 交易所官方页面可作为法定披露和互动信息的权威入口。
- 投资者互动平台信息标记为**补充披露，不替代法定公告**。
- 新闻和公司官网**不得单独支撑关键财务结论**。
- 同一事实若同时有法定公告与新闻传闻且互相冲突，**法定披露优先，并保留冲突记录**。

### 项目里的实际落点

引擎对"推导出来的值"明确标注为 E2 而不是假装是原文披露。典型场景：

- 资产负债表的 **`assets`（资产总计）与 `liabilities`（负债合计）在报表未直接列示时，
  由两个小计相加推导**，标 `derived` / `derived_from` / `derived_from_fact_ids`，
  以 **E2 级证据**返回，并在 `warnings` 里提示"以下总额科目原报表未直接列示，已由小计推导"。
  这类推导值可以参与勾稽，但**必须能被回溯到两个小计**。

- 单季数据由累计数相减推算（`current_ytd_or_annual − preceding_quarter_ytd`）也是 E2，
  且当单季披露值与推算值冲突时**不选择任何一方**，改为进入复核队列。

## 二、四个核心可追溯对象

| 对象 | 字段 | 用途 |
| --- | --- | --- |
| `source_document` | `doc_id, issuer, type, publish_date, cutoff_date, url, sha256, license` | 文档级血缘 |
| `source_span` | `span_id, doc_id, page, bbox, text, table_id` | **最小可引用证据** |
| `financial_fact` | `fact_id, code, period, statement, concept, value, unit, scope, confidence` | 标准财务事实 |
| `metric_value` | `metric_id, formula_version, inputs, value, peer_percentile` | 派生指标与公式 |
| `claim` | `claim_id, text, claim_type, confidence, status` | 报告中的可验证陈述 |
| `claim_evidence` | `claim_id, evidence_id, relation, weight` | **支持、反驳或限定**关系 |
| `scenario` | `scenario_id, assumptions, horizon, owner, timestamp` | 预测情景 |
| `model_run` | `run_id, model, prompt_hash, tool_log, seed, duration, status` | 运行账本 |

注意 `claim_evidence.relation` 有**支持 / 反驳 / 限定**三种取值。
只记录支持关系是不合格的——反证必须作为一等公民进入证据图谱。

## 三、Claim 抽取 JSON 契约

```json
{
  "claim": "回款改善",
  "claim_type": "management_assertion",
  "period": "2025Q4",
  "metric_links": ["accounts_receivable_days", "cfo"],
  "evidence_spans": ["span_1023"],
  "falsifiers": ["回款天数继续上升", "经营现金流未改善"],
  "confidence": 0.72
}
```

字段要求：

- `claim_type` 用于区分**事实、计算结果、模型推断、管理层声称**——四者不能混写。
- `falsifiers`（可反驳条件）**必填**，且必须至少一条。
- `confidence` 是数值，不与环境风险颜色混用。

## 四、矛盾分类与处理

| 类型 | 例子 | 处理方式 |
| --- | --- | --- |
| 数字矛盾 | 正文称收入增长，标准事实表显示同比下降 | **E1 数据优先**，标记文本冲突 |
| 时间矛盾 | 用下一年度解释回填到上一时点 | 按截止日屏蔽后发信息 |
| 口径矛盾 | 公司使用调整后利润，同行使用法定净利润 | **不直接比较**，显示口径差异 |
| 因果不足 | 把相关性描述为成本下降的原因 | 降级为假设并寻找外部价格证据 |
| 遗漏反证 | 只引用管理层解释，忽略现金流恶化 | Critic Agent 强制加入反证检索 |
| 来源等级冲突 | 新闻传闻与法定公告不同 | 法定披露优先，并**保留冲突记录** |

## 五、防止前视偏差

- 所有查询都带 `analysis_cutoff`；**发布日晚于截止日的文档不进入检索**。
- 行情和同行倍数按截止日快照存储；**禁止使用当前值回填历史分析**。
- 预测评测采用滚动回测：仅使用当时可见信息预测下一期，再与真实结果比较。

## 六、本地模型提示词原则

1. 只允许引用检索上下文中的 `span_id`，**不得伪造页码**。
2. 输出严格 JSON Schema；解析失败最多重试两次，之后进入人工复核。
3. 先列事实与未知项，再给推断；**每个推断必须列至少一个可反驳条件**。
4. 模型**不得计算最终财务数值**；只返回需要调用的工具和参数。

通用系统提示词要点：只使用任务上下文、已注册工具和证据库；区分事实、计算结果、推断与建议；
每个事实引用 `source_span`，每个数值引用 `fact_id` 或 `metric_id`；无证据时返回 `UNKNOWN`
不得补全；主动寻找反证与口径差异；只输出指定 Schema；**不得输出投资收益保证**。

## 七、报告使用规则

- 每个关键判断可回溯到原文页码和计算公式（成功判据第 2 条：三次点击以内）。
- 事实与推断必须**在版面上分开**，不能在同一段落里混写。
- 引用完整性是评测项：**Citation precision 精确率不低于 0.95，覆盖率不低于 0.90**。
- **伪造引用属于一票否决**。
