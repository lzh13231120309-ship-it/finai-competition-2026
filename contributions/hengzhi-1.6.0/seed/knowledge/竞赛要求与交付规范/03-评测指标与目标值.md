# 评测体系与目标值

竞赛方案第十一节的硬性评测要求。**不要只展示"回答看起来不错"，要给出可量化成绩。**

## 一、评测集规模建议

| 项目 | 建议规模 |
| --- | --- |
| 公司 | 5 家 |
| 期间 | 3 个 |
| 财务事实 | 至少 150 个 |
| 文本 Claim | 50 条 |
| 异常案例 | 30 个 |
| 报告片段 | 10 份 |

黄金答案由两名队员**独立标注**，分歧由指导教师裁决。

## 二、指标与目标值

| 能力 | 指标 | 目标 |
| --- | --- | --- |
| 表格抽取 | 字段准确率、数值准确率、单位准确率 | **关键三表数值准确率不低于 99%** |
| 科目映射 | 宏平均 F1、低置信度召回 | **常见科目 F1 不低于 0.95** |
| 引用 | Citation precision 与 coverage | **精确率不低于 0.95，覆盖率不低于 0.90** |
| 异常检测 | Top-K 命中率、误报率 | **Top 5 覆盖人工确认的重要异常不低于 80%** |
| 文本矛盾 | 准确率、召回率 | **F1 不低于 0.80** |
| 预测 | 收入与利润 MAPE、方向准确率 | 只与**朴素基线**比较，不承诺绝对阈值 |
| 估值 | 公式单测、边界测试、独立表格复核 | **核心公式 100% 通过** |
| 稳定性 | 同输入重复运行、离线运行、故障恢复 | 数值一致；**三次完整演示成功** |
| 报告质量 | 证据、逻辑、风险、可执行性人工量表 | **平均分不低于 4/5** |

## 三、消融实验（四个对照）

| 实验 | 基线 | 要证明的点 |
| --- | --- | --- |
| RAG 消融 | 无检索的本地 LLM | 证据检索减少数字幻觉 |
| Critic 消融 | 不使用反证 Agent | 反证覆盖和引用精确率提升 |
| 规则消融 | 仅 LLM 阅读年报 | 确定性规则提高稳定性和可复现性 |
| 同行消融 | 只看公司历史 | 同行分位减少对行业周期的误判 |
| 估值联动消融 | 风险与估值分离 | **风险参数化使结论能影响决策** |

## 四、报告评分量表（五维度）

| 维度 | 5 分标准 | 一票否决 |
| --- | --- | --- |
| 事实正确 | 数值、期间、单位和口径全部可核验 | 关键数字错误 |
| 证据充分 | 关键 Claim 均有高等级证据并展示反证 | 伪造引用 |
| 金融逻辑 | 异常、驱动、预测和估值传导一致 | 三表不平或因果倒置 |
| 风险审慎 | 说明不确定性、边界和替代解释 | 收益保证或确定性荐股 |
| 可操作性 | 给出待核验问题与敏感参数 | 只有摘要，没有决策支持 |

## 五、测试金字塔

| 层级 | 内容 | 示例 |
| --- | --- | --- |
| 单元测试 | 公式、单位、期间、边界和缺失值 | 资产负债恒等式、应收天数、FCFF、WACC |
| 契约测试 | Agent、工具与 Schema | **无 `span_id` 的 Claim 必须校验失败** |
| 黄金样例 | 固定 PDF 到固定事实和风险 | 页面、数值、风险排序与引用回归 |
| 集成测试 | 完整 DAG、缓存、重试和恢复 | 解析失败进入人工复核，**不继续估值** |
| 演示测试 | 离线、低内存、模型超时和投影分辨率 | 主机与备机各连续运行三次 |

## 六、必须完成的勾稽测试（方案原文，五条）

1. **资产负债表恒等式在容差内成立**；容差随单位和四舍五入调整。
2. 现金流量表**现金净增加额与资产负债表货币资金变动**进行解释性对账。
3. 利润表净利润与现金流量表**间接法起点一致**，或能够由少数股东口径解释。
4. **各年期初值与上年期末值一致**；重述数据必须标记版本并优先使用重述口径。
5. **合并口径与母公司口径严格分开**；万元、元、亿元全部换算到标准单位。

## 七、关键失败注入（必须能优雅降级）

| 注入 | 期望行为 |
| --- | --- |
| PDF 某页为扫描图片 | 自动切换 OCR 并**降低置信度** |
| 同一科目出现单位"元"和"万元" | 单位校验**阻止写入错误值** |
| 模型输出无法解析 | 修复提示重试两次，随后进入**人工复核** |
| 数据接口离线 | 使用带哈希的快照，**不改变运行输入** |
| 估值参数超出边界 | **拒绝计算并提示允许范围** |

## 八、性能预算

| 阶段 | 目标时间 | 策略 |
| --- | --- | --- |
| 加载演示数据 | 30 秒内 | 预解析与索引 |
| 规则计算 | 10 秒内 | 批量查询 |
| 证据检索 | 单次 2 秒内 | 本地向量索引 + 关键词混合检索 |
| 模型解释 | 单条 20 秒内 | 小模型、结构化输出与缓存 |
| 情景重算 | **2 秒内** | 纯 Python 确定性计算 |
| 报告生成 | 60 秒内 | 模板渲染与已验证 Claim 缓存 |

## 九、复现凭证

每次运行生成 `repro.json`，记录：Git 提交、Docker 镜像、模型文件哈希、Prompt 哈希、
数据 manifest 哈希、参数、随机种子、开始结束时间和输出文件哈希。
答辩时展示同一 `run_id` 如何被 `make reproduce` 复现。

## 十、停止规则（优先级取舍）

- 若第 3 周末仍不能**稳定抽取并核验关键三表**，立即停止扩展文本功能，改为人工校验后的固定数据集。
- 若第 4 周末**三表预测无法勾稽**，简化为收入、利润、营运资本和 FCFF 驱动模型，但保留完整假设与敏感性。
- 若本地模型无法满足现场速度，使用更小模型做分类和抽取，把报告语言生成移到预计算阶段。

**优先级**：P0 = 数据血缘、三表准确、5 条强规则、证据阅读器、三情景估值、离线演示。
P1 = 同行分位、问询闭环、报告 Critic、审计中心、消融实验。P2 = 更多行业模板、自然语言改假设。
**任何不能提高评分或演示稳定性的功能，进入赛后清单。**
