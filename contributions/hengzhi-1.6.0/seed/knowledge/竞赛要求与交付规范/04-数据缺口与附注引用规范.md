# 数据缺口与附注引用规范

报告里写"数据缺口"之前，必须先回答一个问题：**是文档没有，还是我没找到？**

把这两者混为一谈，是财务分析报告里最常见、也最容易被评委抓住的逻辑漏洞——
它会让读者以为"公司隐瞒了信息"，而实际上信息就在附注第 197 页。

---

## 一、三种缺口必须分开写

| 类型 | 代码 | 判据 | 报告中必须怎么写 | 对应证据等级 |
| --- | --- | --- | --- | --- |
| **文档确未披露** | `not_disclosed` | 已用关键词全库检索，确认原文无此信息 | "原文未披露" | — |
| **本工具未抽取** | `not_extracted` | **原文有**，但工具字段覆盖不到（附注、MD&A、分部信息） | "**见附注 X（第 N 页）**" | E1（可引用） |
| **抽取失败 / 待复核** | `unresolved` | 抽到了但置信度低、值冲突、单位或期间不明 | 进复核清单，附候选值 + 理由 | E5（不得进结论） |

**第二条是重点**：只要原文里找得到，就**不允许**写成"数据缺口"。
判断依据是"**是否已定位到原文位置**"，而不是"工具字段里有没有"。

## 二、`disclosure_map`：把"未抽取"变成"可引用"

工具（`analyze_financial_report`）返回的 `disclosure_map` 字段，
就是为"未抽取"这一条准备的。它把 16 类常见分析需求映射到**本次文档里已定位到的披露位置**：

```json
{"需求": "分部/分产品/分区域收入", "原文位置": "附注4（第167页）", "file": "xxx.pdf"}
{"需求": "存货明细与跌价准备", "原文位置": "附注19（第197页）", "file": "xxx.pdf"}
{"需求": "借款利率、期限与担保", "原文位置": "附注27（第206页）", "file": "xxx.pdf"}
{"需求": "股息与派息率", "原文位置": "附注12（第185页）", "file": "xxx.pdf"}
```

**写作纪律**：

1. 写"数据缺口"章节前，**先查 `disclosure_map`**。
2. 需求**在** `disclosure_map` 里 → 写成"**见附注 X（第 N 页）**"，**不是**缺口。
3. 需求**不在** `disclosure_map` 里 → 才可能是真缺口，但仍要说明检索方式
   （用了哪些关键词、覆盖了哪些页），不能只写"缺失"。
4. `disclosure_map` 覆盖不到的**其他**需求，要自己用 `inspect_document` 的
   `query` / `page` 去定位；定位到就引用，定位不到才写"原文未披露"。

`disclosure_map` 是**起点不是终点**——它只保证常见需求有定位，不替代实际的原文阅读。

## 三、`review_queue` 是"待复核"，不是"已排除"

工具返回的 `review_queue` 里每一条都是**尚未解决的事项**，例如：

| 复核代码 | 含义 |
| --- | --- |
| `unresolved_metadata` | 缺少期间类型（时点/区间）等元数据 |
| `statement_mismatch` | 归属报表与科目定义不符（如把利润表科目挂在资产负债表下） |
| `subject_alias_collision` | 同名科目跨表碰撞（同一名称在两处含义不同） |
| `sign_convention_mismatch` | 符号约定冲突（现金流量表间接法负号 vs 附注正号） |
| `excluded_fact` | 因口径/期间无法确定而被排除的事实 |
| `summary_conflict` | 摘要页与主表数值冲突（超出舍入容差） |

**硬性纪律**：不能删除待复核事项后宣称"报告已全部核验"。
复核清单必须原样出现在交付物里，并说明每一条的处理状态
（已解释 / 已用替代来源 / 仍未解决）。

## 四、附注引用的写法格式

引用必须**可点击、可定位、可复算**（成功判据：三次点击以内回到原文）。

### 正确写法

- `存货 58.46 亿元，其中原材料占比见附注 19（第 197 页）`
- `分部收入及增速见附注 4（第 167 页）；本报告未对其做口径调整`
- `有息负债 44.93 亿元（指标 interest_bearing_debt，= borrowings + lease_liabilities）`

### 错误写法

| 错误写法 | 问题 |
| --- | --- |
| `存货明细缺失` | 原文有（附注19），是"未抽取"，必须给定位 |
| `详见年报` | 无页码，不可定位 |
| `根据公开资料` | 无文件名、无页码，等于无证据 |
| `预计/大概/约` + 数字 | 把未核验的推算值写成确定值 |
| `（第 5 页）` 但实际在第 197 页 | **伪造引用属于一票否决** |

## 五、缺口清单模板

交付物的"数据缺口"章节按下表组织，三列缺一不可：

| 需求项 | 类别 | 定位 / 说明 |
| --- | --- | --- |
| 分部收入明细 | not_extracted | 见附注 4（第 167 页） |
| 前五大客户集中度 | not_disclosed | 已检索"前五名客户""客户集中度""客户 A"等关键词，覆盖全文 320 页，原文未披露 |
| 2024 年折旧摊销（母公司口径） | unresolved | 附注仅披露合并口径；母公司表未列示，列为待复核 |
| 利息收入明细 | not_extracted | 见附注 8（第 173 页） |

## 六、常见表述错误对照

| 你写的 | 应该写的 |
| --- | --- |
| "公司未披露分部数据" | "分部数据见附注 4（第 167 页）" |
| "现金流量表补充资料缺失" | "现金流量表补充资料见附注 8（第 173 页）" |
| "无法获取 2024 年折旧摊销" | "2024 年折旧 27.28 亿元、使用权资产折旧 1.36 亿元、摊销 0.11 亿元（第 121 页）" |
| "净现金约 253 亿元" | "净现金 177.73 亿元（= 现金及银行结余 111.78 亿 + 长期银行存款 110.88 亿 − 有息负债 44.93 亿）；若将 75.55 亿 FVTPL 理财计入则为 253.28 亿，口径更宽" |
| "待复核事项 98 条，已处理" | "待复核 26 条，逐条列出处理状态" |

## 七、交付前的五条硬检查

1. 报告里**没有任何**"缺失/未披露"的字样指向一个实际能在附注找到的项目。
2. 每一条附注引用都带**具体编号 + 页码**，且页码能核对回原文。
3. `review_queue` 的事项全部出现在交付物里，且标了处理状态。
4. 缺口清单按 `not_disclosed` / `not_extracted` / `unresolved` 三分类，没有混写。
5. 凡写"未披露"的，都能说出检索用了哪些关键词、覆盖了哪些范围。
