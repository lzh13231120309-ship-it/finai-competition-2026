# 公告字段模板与跨字段勾稽

公告抽取的失分点不在"抽不到"，而在**抽到了但算不通**：比例分母用错、累计与本次混填、
日期先后颠倒。本条目给出 9 类公告的字段模板与程序会跑的勾稽规则，
使抽取结果在交付前能自证一致。

## 一、9 类公告的字段模板

### 1. `pledge` 股权质押

`股东名称`、`质押股数_股`、`占所持比例_百分`、`占总股本比例_百分`、`质权人`、
`质押起始日`、`质押到期日`、`质押用途`、`是否补充质押`

### 2. `release` 解除质押

`股东名称`、`解除质押股数_股`、`占所持比例_百分`、`占总股本比例_百分`、`质权人`、
`质押起始日`、`解押日期`

### 3. `extension` 质押展期

`股东名称`、`展期股数_股`、`占所持比例_百分`、`占总股本比例_百分`、`质权人`、
`质押起始日`、`原质押到期日`、`展期后到期日`、`质押用途`

### 4. `holding` 股东持股

`股东名称`、`持股数量_股`、`持股比例_百分`、`累计质押股数_股`、
`累计占所持比例_百分`、`累计占总股本比例_百分`

### 5. `bid` 中标

`项目名称`、`招标人`、`中标人`、`中标金额_元`、`阶段`、`工期_日历天`

### 6. `contract` 重大合同

`合同名称`、`甲方`、`乙方`、`合同金额`、`币种`、`签订日期`

### 7. `freeze` 司法冻结

`股东名称`、`冻结类型`、`冻结股数_股`、`占所持比例_百分`、`占总股本比例_百分`、
`起始日`、`到期日`、`冻结申请人`

### 8. `shareholding_change` 股东增减持

`股东名称`、`变动方式`、`变动股数_股`、`变动比例_百分`、`变动期间起`、`变动期间止`、
`成交均价_元`、`变动前持股_股`、`变动前持股比例_百分`、`变动后持股_股`、`变动后持股比例_百分`

### 9. `equity_report` 权益变动报告书

`信息披露义务人`、`上市公司名称`、`股票代码`、`权益变动性质`、`签署日期`

> 事件族归并：`pledge` / `release` / `extension` / `holding` 同属 **pledge 族**。
> 一份公告里多股东同时质押、或同时有本次与累计，会切出**多条记录**，不要合并成一条。

## 二、两个比例分母（最高频的填反错误）

质押/冻结/增减持类公告同时给两个比例，**分母不同、极易互换**：

| 字段 | 分母 | 说明 |
| --- | --- | --- |
| `占所持比例_百分` | **该股东自己的持股数** | 反映该股东的质押/冻结程度 |
| `占总股本比例_百分` | **公司总股本** | 反映对公司整体的影响 |

程序会分别反算核对（见下节 `PCT_TOTAL_MISMATCH` / `PCT_HOLD_MISMATCH`）。
填反时两个比例都落在合理区间（0–100），**不会报错，只会静默错**——这是最危险的一类错误。

## 三、程序会跑的跨字段勾稽（不符只进 review，不改数）

| 规则码 | 触发条件 | 严重度 |
| --- | --- | --- |
| `PCT_RANGE` | 任一比例不在 0–100 | error |
| `PCT_TOTAL_MISMATCH` | `质押股数 ÷ 总股本 × 100` 与披露的 `占总股本比例_百分` 不符（容差 max(0.02, 1%)） | warn |
| `PCT_HOLD_MISMATCH` | `质押股数 ÷ 该股东持股数 × 100` 与披露的 `占所持比例_百分` 不符 | warn |
| `CUM_LT_EVENT` | `累计质押股数_股` **小于** 本次质押股数 | error |
| `CUM_GT_HOLD` | `累计质押股数_股` **大于** 该股东 `持股数量_股` | error |
| `END_BEFORE_START` | 到期日不晚于起始日（含展期后到期日） | error |
| `RELEASE_BEFORE_START` | 解押日早于质押起始日 | error |

隐含总股本：正文未给总股本时，程序用各股东 `持股数量_股 ÷ 持股比例_百分 × 100` 反推并取中位数——
**反推值必须标注为推算**，不得当成披露值引用。

## 四、五类"没有数据"必须分开（与定期报告同一纪律）

| 类型 | 判据 | 必须怎么写 |
| --- | --- | --- |
| 文档确未披露 | 已用关键词全库检索，确认原文无此信息 | "原文未披露" |
| 本工具未抽取 | 原文有，但 schema 覆盖不到 | "见第 N 页 / 附注 X"，必须给定位 |
| 原文声明以外部为准 | 出现"以…文书为准""另行公告""尚待确认" | **填 `null`**，并引用该短语作为理由 |
| 表格空值 | 原文用"—""–""-"表示 | **填 `null`，不是 0** |
| 抽取失败/待复核 | 抽到但置信度低、值冲突 | 进复核清单，附候选值与理由 |

**`0` 与 `null` 是两回事**：明确写"累计质押 0 股"就必须输出 0；写"—"才是 null。

## 五、操作检查

1. 先跑 `extract_announcement_fields` 做机械归一（大写金额、万元/万股量级、日期、百分数小数形式），
   再跑 `extract_announcement_records` 拿结构化记录。
2. 逐条核对 `checks`：`level` 为 `error`/`warn` 的**必须**处理或写入"待人工核验"。
3. 比例填反的检查方法：把两个比例分别乘以两个分母，看哪一个能对上披露的股数。
4. 股数单位：`1,500 万股` = `15,000,000 股`，**万股/股混用是千倍级错误**。
5. 日期：公告日 ≠ 事件日。质押起始日、到期日、解押日要分别取，不能都用公告日。
6. 多笔交易拆成多条记录；"拟减持不超过 X%"是**计划上限**，不是已发生事实。
7. 减持数量为负或明确标注方向，不要一律填正数。
8. 抽完过一遍 `validate_structured_output`（验格式与原文支持，不证明语义关系）。

## 六、交付检查

- 交付物是结构化数据（JSON/表格），不是自然语言段落。
- 每个有值字段都有页码 + 连续原文摘录；归一化值与原文原值同时保留。
- 单位、期间、口径三项没有一项是"默认猜的"。
- 两个比例的分母已核对（占持股 vs 占总股本）。
- 缺失字段按五分类标注；凡"未抽取"都给了页码定位。
- 未披露填 `null` 而非编造值；表格"—"填 `null` 而非 0。
- "合计"行没有被当成数据条目。
- 记录文档 SHA256 与 `run_id`，可复现。

## 资料性质与回答边界

本文为原创任务知识与分析方法，官方来源用于支持上市公司临时公告的披露义务，
字段模板、勾稽规则码与操作清单来自本项目 `server/announcement_records.py` 的实现与作者解释，
不是准则或交易所指引原文。核验截止为 2026-10-12。
字段模板只覆盖引擎已支持的 9 类公告；业绩预告、重大资产重组、诉讼等不在覆盖范围，
