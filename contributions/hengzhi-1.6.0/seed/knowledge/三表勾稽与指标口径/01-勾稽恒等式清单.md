# 三表勾稽恒等式清单

勾稽（tie-out）是**唯一能在无人监督下自动发现数据错误**的机制。
每个恒等式都写成「系数组合 = 0」的形式，差额超出容差即为 `fail`。

> 容差**随单位和四舍五入调整**，用舍入量子（该单位 1 个最低有效位的量级）计算，
> 不能写死一个绝对值。会计恒等式不成立时，**先怀疑单位、口径、期间，再怀疑数据本身**。

---

## 一、时点值勾稽（资产负债表，instant）

| 检查代码 | 恒等式 | 说明 |
| --- | --- | --- |
| `balance_sheet_equation` | `assets − liabilities − equity = 0` | 会计恒等式。依赖推导总额，属**半循环** |
| `balance_sheet_identity` | `current_assets + noncurrent_assets − current_liabilities − noncurrent_liabilities − equity = 0` | **非循环**：直接用四个小计与权益，验证"报表本身平不平" |
| `asset_subtotals` | `assets − current_assets − noncurrent_assets = 0` | 资产小计加总 |
| `liability_subtotals` | `liabilities − current_liabilities − noncurrent_liabilities = 0` | 负债小计加总 |
| `equity_subtotals` | `equity − parent_equity − minority_equity = 0` | 权益小计加总 |

**为什么要单独做 `balance_sheet_identity`**：
`balance_sheet_equation` 里的 `assets` / `liabilities` 在报表未直接列示时是由
两个小计相加**推导**出来的（E2 级证据）。如果只用它做检验，
"推导出的总额"与"推导出的权益"当然会平——那是**循环论证**，什么都验证不了。
`balance_sheet_identity` 不依赖推导总额，因此提供了真正独立的验证。

> 注意 `parent_equity`（归母权益）在某些扫描件里确实**没有独立数值行**，
> 它只出现在权益变动表的矩阵里。此时 `equity_subtotals` 无法执行——
> 这是数据限制，不是缺陷，应在交付物里说明未覆盖范围。

## 二、区间值勾稽（利润表 + 现金流量表，duration）

| 检查代码 | 恒等式 | 说明 |
| --- | --- | --- |
| `net_profit_equation` | `net_profit − profit_before_tax + income_tax = 0` | 净利润 = 税前利润 − 所得税 |
| `profit_attribution` | `net_profit − parent_net_profit − minority_profit = 0` | 净利润在归母与少数股东之间的分配 |
| `pretax_profit_equation` | `profit_before_tax − operating_profit − nonoperating_income + nonoperating_expense = 0` | 税前利润 = 营业利润 + 营业外收入 − 营业外支出 |
| `cash_equivalents_rollforward` | `cash_equivalents_end − cash_equivalents_start − cash_equivalents_change = 0` | **现金及等价物期初期末滚动** |
| `cash_flow_components` | `cash_equivalents_change − operating_cash_flow − investing_cash_flow − financing_cash_flow − fx_cash_effect = 0` | 现金净增加额 = 三活动 + 汇率影响 |

**`cash_equivalents_rollforward` 是最有价值的回归探针**：
它同时校验"期初 = 上年期末"和"变动额"两次一致性。
如果列→期间的映射做错了（例如双列表格的前一期被错标成最新期），
这条会**立即失败**，而不是静默产出错误数据。

## 三、跨表对账（方案明文要求的五条）

1. **资产负债表恒等式在容差内成立**。
2. 现金流量表**现金净增加额与资产负债表货币资金变动**进行解释性对账。
3. 利润表净利润与现金流量表**间接法起点一致**，或能由少数股东口径解释。
4. **各年期初值与上年期末值一致**；重述数据必须标记版本并优先使用重述口径。
5. **合并口径与母公司口径严格分开**；万元、元、亿元全部换算到标准单位。

第 2 条有个真实陷阱：**「现金及现金等价物」与「现金及银行结余」是两个不同的数**。

- 现金流量表的期末现金 = 现金及现金等价物口径。
- 资产负债表的货币资金 = 现金及银行结余，可能包含受限存款、
  三个月以上定期存款等**不属于现金等价物**的项目。

两者**不应被当成同科目冲突而一起废掉**。处理方式：
给科目指定"归属报表"（`HOME_STATEMENT`），冲突时保留归属报表里的那一个，
并把跨表差异记为 `statement_mismatch` **复核类别**而不是 `duplicate_conflict`。

## 四、失败反查（`tieout_diagnosis`）

恒等式失败时的**单变量数量级替换**反查流程：

1. 依次尝试把每个参与科目乘以/除以 1000、10000、1000000 等数量级。
2. 若存在唯一组合使恒等式在容差内成立，输出该组合作为建议：
   `resolution: unit_misplacement` + 建议的单位量级 + 依据。
3. 若多个组合都能成立，输出 `resolution: ambiguous` —— 表示
   **多个科目同时错，必须转人工**，不要硬猜。
4. **写明建议，但绝不自动改数。** 系统只提示，人工确认后才改。

## 五、推导总额（E2 级证据）

报表未直接列示 `assets`（资产总计）或 `liabilities`（负债合计）时，
由两个小计相加推导，并打标：

```
derived: true
derived_from: ['current_assets', 'noncurrent_assets']
derived_from_fact_ids: [...]
```

这类值以 **E2 级证据**返回，且必须在 `warnings` 里显式提示
"以下总额科目原报表未直接列示，已由小计推导"。
**推导值可以参与勾稽，但必须能被回溯到两个小计。**

### 五之二、摘要页值要被精确小计替换

`assets` / `liabilities` 若「摘要页有、主表小计也有」，用**小计相加**替换摘要值：

- 摘要页按百万元四舍五入，主表小计是千元精确值；
- 实测 2025 年总资产：摘要 65,169,000,000 元 vs 小计相加 65,169,128,000 元，
  差的 128,000 元会让资产负债表恒等式**永远平不了零**（差异从 0 变成 128,000）；
- 替换条件是"小计全部为 `primary` 且现存的总额只有 `summary`"，
  两个条件都满足才替换；
- **原值不丢**：摘要页那条事实仍在结果里，只是不再作为该组的代表。
  替换动作在 `warnings` 里标注「替换摘要页四舍五入值」。

### 五之三、母公司拥有人应占权益的推导

港式權益區块常只写「母公司擁有人 / 應佔權益」两行**标题**，
不印合计数字（合计就等于权益总额）。缺了它，归母口径的 ROE 直接算不出来。

判据要求**三处互相印证**才敢推导，缺一不推：

1. 没有单独披露少数股东权益 —— 有的话一定会有合计行，不必推；
2. 股本、储备都取到了；
3. **股本 + 储备 与权益总额在舍入容差内一致**（这是交叉验证）。

任一条不满足 → 不推导，并在 `warnings` 记明差异，
避免把"还有未取到的科目"硬当成零。

## 六、单季数据推导

对 `ytd` / `annual` 且期末月为 6 / 9 / 12 的报告：

```
单季值 = 本期累计 − 上一季度累计     # 期限 < 当前期
```

护栏：

- **重述标记不一致**（一个重述、一个没重述）→ **不相减**，进 `restatement_mismatch` 复核。
- 单季推算值与单季**披露值**冲突 → **不选择任何一方**，进 `quarter_conflict` 复核。
- 冲突判据用三条舍入量子之和，不用相对百分比。
- 资产负债表科目、每股类科目、`cash_equivalents_start/end` **不参与单季推算**
  （时点值没有"单季"概念，现金滚动项是跨期量）。
