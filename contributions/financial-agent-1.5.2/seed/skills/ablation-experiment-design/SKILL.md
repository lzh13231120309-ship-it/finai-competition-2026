# 消融实验设计

竞赛第三节要求四个对照（RAG / Critic / 规则 / 同行 / 估值联动共五项）。
这个技能只解决一件事：**把"我加了个模块，效果更好了"变成评审能复算的对照表。**

绝大多数作品的消融实验是编的——"加入检索后准确率提升 15%"这种句子，
既没有基线定义，也没有可复现的测量口径。本技能的目标是让每一个数字都能被复算。

## 三条硬纪律

1. **一次只改一个变量。** baseline 与 treatment 之间的输入、代码路径、参数必须完全相同，
   唯一差别就是被消融的那一层。做不到这一点，差异就不能归因。
2. **只报可测的指标。** 无法实测的（例如"LLM 采样的方差"）写成"结构性判断"，
   不要混进实测结果里冒充数据。宁可指标少，也不要指标假。
3. **数据不足就说不足。** 返回 `insufficient_data` 是**正确**输出，不是失败。
   拿不到第二家公司就构不出同行分位，此时如实写"该对照数据不足"。

## 执行入口

先检查当前环境真实可用的工具，不要凭本技能描述假定工具存在。

- **本地金融 Agent（FinSleuth）**：调 `run_ablation(run_id=A, forensic_run_id=F, ...)`
  - `peer_run_ids=[同业1, 同业2, ...]`：同行消融用，≥1 家才有效
  - `synthetic_peers=N`：拿不到真实同业时的机制演示，**报告必须写明是模拟**
  - `report_path=...`：提供后把报告引用精确率纳入 RAG / Critic 消融
- **命令行**：`python -m server.finance_cli ablate --input 年报.pdf --peer-run 同业.json
  --synthetic-peers 4 --report 报告.docx --output 输出目录`
- **其他 harness**：先跑 `python -m server.finance_cli --help`，再查 `ablate --help`。
  以帮助输出为准，不猜测未列出的选项。
- **缺少项目工具**：可以手工搭对照，但必须明确写出"以下对照未经项目引擎复算"，
  并说明基线如何构造、指标如何测量。不要声称用了本技能的五组对照框架。

## 五组对照的基线与判据

| 实验 | 基线 | 实验组 | 判据（满足才算"支持"） |
| --- | --- | --- | --- |
| RAG 消融 | 抹掉全部 `evidence_ids` | 完整证据编号 | 引用可核验率：基线 0、实验组 > 0 |
| Critic 消融 | 反证/未解问题/传导路径字段置空 | 三条字段齐全 | 反证覆盖率：基线 0、实验组 = 1 |
| 规则消融 | `checks=[]`（不跑勾稽） | 全部恒等式 | 注入"×1000"错误后实验组检出、基线 0 检出；且重复运行一致 |
| 同行消融 | `peer={}`（只看公司历史） | 同行分位 | 有规则获得真实分位加权，且能区分"区间内"与"偏离" |
| 估值联动 | `findings=[]` | 真实 findings | 基线压力情景 = 基准情景（差额 0），实验组差额 ≠ 0 |

## 写进报告时的要求

- **每个结论都要带基线。** 只写"实验组更好"不构成证据，必须写清基线是什么、
  差异有多大、用什么口径测的。
- **"两侧相同"的指标要照实写。** 例如反证字段不改变报告的引用集合，
  引用精确率两侧就相同。挑对自己有利的指标呈现会削弱整份材料的可信度。
- **"0 条勾稽不符"是正确结果。** 真实年报三表本来就是平的，不要为了显得有产出
  把它写成"未检出问题"或暗示引擎失灵。引擎的价值之一是能给出**已核验通过**。
- **模拟数据必须标注。** 用了 `synthetic_peers` 就写明"本次同行样本含 N 家模拟公司，
  结论仅用于演示机制，不得作为真实同行结论提交"。
- **可复现性要给证据。** 引用 `repro.json` 里的代码指纹、Prompt 哈希与输出哈希；
  规则消融里的"重复运行一致"要给出发现集合的指纹。

## 常见错误

- 把"LLM 直读年报"当成真实基线去跑：LLM 采样不可复现，跑出来的数字无法作为对照。
  正确做法是用**结构消融**（关闭确定性规则 / 抹掉证据字段）构造基线，并明确标注。
- 用同一份数据既做基线又做实验组，只是换了措辞：那不是消融，是重复。
- 指标只报绝对数不报口径：写"准确率 95%"而不写"在多少条样本上、什么算命中"。
- 把 `insufficient_data` 悄悄改成"支持"：这是最严重的一类问题，直接摧毁可验证性。
