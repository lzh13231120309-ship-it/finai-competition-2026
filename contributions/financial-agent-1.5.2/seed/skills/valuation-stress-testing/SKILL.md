# 估值压力测试（风险联动估值）

这个技能只解决一件事：**让"发现的风险"进到模型里**。多数作品停在"算了一堆比率"，
做不出"回款天数拖到压力情景，DCF 区间实时下降"这个闭环。本技能就是补这一环。

硬纪律：**压力情景里"这家公司特有的"那部分参数必须由法证发现推导出来，不允许手填一个悲观数字了事。**
每一条证据驱动的参数改动都要能回答"是哪个 rule_id 让我这么改的"。

但压力情景同时还有第二层——**结构性情景兜底**（增速下调、毛利率压缩、回款天数拉长、
折现率上调等一组行业通用下行假设）。它存在的理由很具体：如果压力情景完全由法证发现驱动，
那么当扫描没有产出发现时（数据干净，或调用方没传 findings），压力情景会与基准情景**逐位相同**——
三情景数值一模一样，报告上看不出任何异常，而"压力测试"其实什么都没测。

两层的关系是**证据优先、兜底填缝**：证据动过的参数由证据决定，兜底让位（避免双重计算）；
证据没覆盖的参数才由兜底填补（避免温和的证据被吞掉）。
报告必须把这两层分开说，不能把情景假设说成证据结论。

## 执行入口

先检查当前环境真实可用的工具，不要凭本技能的描述假定工具存在。

- **本地金融 Agent（FinSleuth）**：严格按顺序调用
  1. `analyze_financial_report(filenames=[...])` → 拿 `run_id`（记为 A）
  2. `forensic_scan(run_id=A, peer={...})` → 拿 `run_id`（记为 F）
  3. `scenario_valuation(run_id=A, forensic_run_id=F)` → 三情景估值

  三个 ID 必须真实串联，不要凭记忆重述上一步结果。若跳过第 2 步，`scenario_valuation`
  会自动取最近一次法证运行；若一次都没跑过，压力情景只剩结构性兜底、**证据驱动部分为 0**——
  引擎会在 `stress_diagnostic.evidence_backed` 标为 false 并在报告里要求说明，
  但不要因此认为"压力情景有了就等于风险测过了"：那只是情景假设，不是这家公司的风险。
- **其他 harness**：在本项目目录先跑 `python -m server.finance_cli --help`，再查子命令
  `--help`。有 `.venv/bin/python` 就优先用它。以帮助输出为准，不猜测未列出的选项。
- **缺少项目工具**：可以手工搭 DCF，但必须明确写出"以下估值未经项目引擎复算"，
  并说明 FCFF、终值、净债务桥接的具体口径，不要声称用了本技能的三情景框架。

## 工作流程

1. **确认建模输入齐了**：读 `scenario_valuation` 返回的 `data_quality`、`degraded_inputs`
   与 `missing_inputs`。
   `revenue_base`（营业收入基数）是唯一的硬性输入；缺它时 `ok=false`，**不要用默认值偷偷填平**，
   先回去解决提取问题。`net_debt`、`non_operating_assets`、`shares` 等属于"降级输入"：
   缺失不会让估值跑不出来，但会让权益价值系统性偏高/偏低，必须在交付物里写明
   "未扣净债务"或"未加回非经营性资产"。`from_default_assumptions` 里的变量一律要标注为假设。
2. **先看基准情景区间是否合理**：把 `scenarios.base.parameters` 与公司实际历史对比。
   引擎已用真实费用科目校准 `opex_ratio`、用周转天数指标初始化营运资本、
   用所得税/利润总额校准税率、用有息负债与类现金指标算净债务，
   并把每一项的来源写在 `assumption_sources` 里 —— 写假设表时逐项引用，不要自己复述。
   但**默认的 WACC 与永续增长率是行业中性值，不是这家公司的**——
   如果结果与市场明显背离（引擎会用隐含 EV/EBITDA 与 P/E 在常识区间外告警），
   用 `overrides` 换成有依据的值，并在假设表里写出依据。
   另外核对 `calibration_checks` 里的 `ebit_calibration`：
   模型隐含 EBIT 与「利润总额 + 财务费用」差异超过 15% 时会告警，
   说明期间费用率可能遗漏了重要的损益项目，必须在交付物里说明。
3. **核对压力情景真的动了，并分清两层来源**：读 `stress_diagnostic` 与 `risk_adjustments_stress`。
   每一项调整都应是一个 `{source, parameter, from, to, path}`，其中 `source` 要么是
   `rule_id + title`（证据驱动），要么是"结构性压力兜底"（情景假设）。
   - `from == to` 表示该规则**没有真正改变参数**（方向或映射有问题），要单独说明。
   - `structural_floor_adjustments` / `floor_applied` 里 `binding=false` 的项表示
     "该参数已被证据覆盖，兜底让位"——**不要把它当成一次额外的压力重复计数**。
   - `evidence_backed=false` 表示本轮扫描没有产出可传导的发现，压力情景完全由结构性假设构成。
     报告中必须写明这一点：该情景检验的是"假设恶化时结论是否稳健"，
     而不是"已识别的具体风险被量化"。
   - `stress_diagnostic.insufficient = true` 表示压力情景与基准情景的权益价值差异
     不足 2%，**本次压力测试没有构成实质压力**。报告中必须写明这一点，
     不得把该结果当作"风险已充分量化"。
   - `unmatched_risks` 列出"没定义传导路径"或"参数缺失"的规则。这两类必须在交付物里
     列为**待补假设**，不能静默丢掉——否则压力情景看起来跑通了，其实漏了风险。
   - 若 `stress` 的价值 ≥ `base`，先怀疑不是模型错，而是规则方向与情景语义打架
     （例如某规则上调终值增长率）。逐条读 `path` 找原因。
4. **读敏感性矩阵**：`sensitivity_base` 是 WACC × 永续增长率 的二维矩阵（默认 ±2 步）。
   看区间宽度，不看单点。终值占比 > 75% 时引擎会警告——此时结论几乎全由永续假设决定，
   必须把矩阵放进交付物，不能只给一个数。
5. **读拒绝计算的原因**：`dcf()` 在 `g >= WACC` 时**返回 `ok=false` 而不是硬算**。
   见到这个警告不要改代码绕过，回去检查假设：永续增长率不可能长期高于折现率。
6. **交付**：输出三情景的权益价值区间 + 每情景关键驱动变量表 + 压力传导来源表 +
   敏感性矩阵 + 明确的不确定性说明。

## 传导表（法证发现 → 估值参数）

压力情景只消费这 14 条映射。完整阈值与方向见
[估值契约](references/valuation-contract.md)。

| rule_id | 动哪个参数 | 路径 |
| --- | --- | --- |
| `R_AR_01` | `receivable_days` ↑ | 应收天数上升 → 营运资本占用增加 → FCFF 下降 |
| `R_INV_01` | `inventory_days` ↑ | 存货天数上升 + 跌价率 → 现金占用与减值损失增加 |
| `R_CFO_01` | `wacc` ↑ / `terminal_growth` ↓ | 盈利现金含量不足 → 风险溢价上调、终值增长率下调 |
| `R_MARGIN_01` | `gross_margin` ↓ | 毛利率向同行回归 → EBIT 与终值下降 |
| `R_NREC_01` | `sustainable_profit_discount` ↑ | 扣非口径下调可持续利润 → 整条 FCFF 流折让 |
| `R_GW_01` | `impairment_to_revenue` ↑ | 首年一次性税前减值 → EV 与净资产同步下降 |
| `R_DEBT_01` | `net_debt` ↑ | 短债缺口 → 净债务增加 → EV 转权益价值下降 |
| `R_SETTLE_01` | `receivable_days` ↑ | 收现比偏低 → 营运资本占用 → FCFF |
| `R_EXP_01` | `opex_ratio` ↑ | 期间费用率上调 → EBIT 与终值下降 |
| `R_OCF_01` | `near_term_fcff_haircut` ↑ | 经营现金流恶化 → 近端两年 FCFF 折减 |
| `R_CAP_01` | `capex_to_revenue` ↑ | 资本开支强度上升 → FCFF 分子减少 |
| `R_RPT_01` | `sustainable_profit_discount` ↑ | 体外资金占用 → 可分配利润低于账面 → 估值基数折让 |
| `R_DISC_01` | `data_confidence` ↓ | 关键科目缺失 → 全部结果降级为参考值 |
| `R_TIEOUT_01` | `data_confidence` ↓ | 数据可信度不足 → 全部结果降级为参考值 |

改动幅度 = `step × SEVERITY_WEIGHT[severity]`（critical 1.0 / high 0.7 / medium 0.4 / low 0.15）。
所以**严重度标错会直接改变估值**——这也是为什么法证层的 severity 必须逐条复核。

## 输出纪律

- **输出区间，不输出目标价。** 三情景权益价值是"按情景分布的合理价值区间"，
  不是目标价，也不构成投资建议。交付物里必须原样保留这层免责。
- 每个关键数字都要能回答"参数从哪来"：历史值（哪一期）、同行值（哪几家的中位数）、
  还是规则推导（哪个 rule_id）。没有来源的就是假设，要显式标注为假设。
- 金额一律用 `Decimal`，比例用分数（0.2 = 20%）。前端展示再做百分比格式化，不要在计算层四舍五入。
- **不修改原始事实、不覆盖既有运行结果。** 需要改假设就用 `overrides` 显式覆盖，
  并在交付物里说明改了什么、为什么。
- 三表不平、单位错位、口径未统一时，**先修数据再估值**。用待核验数据跑出来的区间没有意义。

交付物至少包含：运行 ID、输入事实清单（含期间与口径）、三情景驱动变量对照表、
压力传导来源表（含未匹配规则）、权益价值区间、敏感性矩阵、终值占比、
以及明确的"未覆盖范围"与"未扣项/未加回项"。

## 怎么证明"风险联动"真的起作用

写完三情景后，**不要自己声称"风险已进入模型"**，用 `run_ablation` 的「估值联动消融」取数：
baseline 传 `findings=[]`、treatment 传真实 findings，两侧只差这一个变量。

注意：因为压力情景现在有结构性兜底，**baseline 的压力情景不再与基准情景完全相同**。
消融实验因此把对照量换成了「证据传导在结构性下限之上的增量（个百分点）」——
两侧的兜底完全相同，这个差额才是纯证据效应。读它，而不是读两侧的压力情景差额本身。

- 增量为 0：说明本轮发现的严重度不高于结构性兜底，压力情景主要由情景假设而非证据决定。
  报告必须写明这一点。
- 增量不为 0：这才是"风险参数化使结论能影响决策"的量化证据。

另外注意引擎的 `stress_diagnostic.insufficient`：若差异不足 2%，它会在报告里要求写明
"本次压力测试没有构成实质压力"。这是**必须照写**的结论，不得把该结果当作风险已充分量化。
