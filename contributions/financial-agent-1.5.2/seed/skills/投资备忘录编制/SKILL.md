# 投资备忘录编制

把财报分析、法证筛查、同行分位、情景估值四条线**整合成一份能支撑决策的买方文档**。
它本身不产生新数字 —— 所有数字都来自前四步的工具产出。

## 合规红线（先看这一节，比章节结构更重要）

竞赛的一票否决项里有「**收益保证或确定性荐股**」。备忘录是最容易踩这条线的体裁，
因为它天然想给结论。所以：

| 不要写 | 改成 |
| --- | --- |
| 目标价 35 元 | 三情景价值区间 26.35–31.31 元/股，中位情景 27.86 元/股 |
| 给予「买入」/「增持」评级 | 当前价格隐含收入增速 X%、毛利率 Y%，与该水平的差距是 Z |
| 预计股价上涨 30% | 若收入增速维持 15% 且毛利率不低于 58%，权益价值约 X 元 |
| 强烈推荐 | 值得进一步核验的点是 A、B、C；不确定的是 D、E |
| 业绩将超预期 | 触发条件：Q1 收入增速 > X%；反向信号：毛利率低于 Y% |

**判断可以明确，措辞必须条件化。** "如果 A 成立则 B" 是专业判断，
"A 一定会带来 B" 是收益承诺。这条线不能越。

## 执行入口

七章里有五章的数字来自工具，按下面的顺序跑，每一步都用真实返回的 `run_id`：

```
analyze_financial_report(filenames)          → run_id（事实 + 指标 + 勾稽 + 复核队列）
  ├─ forensic_scan(run_id)                   → 风险信号 + 反证方向 + 估值传导
  ├─ peer_benchmark(run_ids=[...])           → 同行分位（五家，MVP 硬指标）
  └─ scenario_valuation(run_id, forensic_run_id, overrides)
                                             → 三情景价值区间 + 每股区间 + 敏感性矩阵
audit_report(run_id, text=<备忘录正文>)      → 交付前自检（必须做）
```

- **其他 harness**：本项目目录下 `python -m server.finance_cli --help`，
  用 `analyze` / `forensic` / `valuation` / `audit` 四个子命令。
  有 `.venv/bin/python` 就优先用它。以帮助输出为准，不猜测未列出的选项。
- **缺少项目工具**：可以按可见材料写备忘录，但必须写明"以下数字未经项目引擎复算"，
  并给出每个数字的原始出处；不要声称做过情景估值或同行分位。

## 七章结构与各章取数

### 1. 投资摘要（一页）
- **核心逻辑三点**，每点一句、各带一个关键数字与证据锚点。
- **价值区间**：用 `scenario_valuation` 的 `range.text` 与 `value_per_share_text` 原样引用。
- **最重要的一条风险**：从 `forensic_scan` 的 Top 1 发现里取。
- **待核验清单摘要**：`review_count` 的条数，从工具字段原样抄，不要自己数。

### 2. 公司概况与商业模式
- 来源是**原文与附注**（`inspect_document`），不是财务指标。
- 收入构成、地区分布、主要客户与供应商集中度 —— 每条给页码。
- 没有披露的项写「原文未披露」，不要用行业常识补。

### 3. 行业与竞争格局
- **同行分位是这一章的核心**：用 `peer_benchmark` 的 `metrics` 表，
  把目标公司在毛利率、净利率、周转天数、杠杆上的位置写出来。
- `outliers` 里列出的指标是重点 —— 它们是"这家公司与同行不一样"的地方，
  要么是竞争优势，要么是需要解释的异常，二选一必须给判断。
- `aligned=false` 时**必须写明**各公司报告期不一致，否则差异里混着行业周期。
- 同行名单与选取依据（行业、业务相似度、规模）要写出来；用户没给同行数据就写
  "本次未做同行比较"。

### 4. 财务分析与预测
- 用 `analyze_financial_report` 的指标与公式，不要心算。
- **必需科目数值必须出现**：营业收入、净利润、归母净利润、经营活动现金流净额、
  资产总计、所有者权益合计。读者没有这些数就无法复算任何比率。
- 盈利、现金转化、营运效率、偿债四块各给一段，每段结论后跟指标代码或页码。
- 预测部分用 `scenario_valuation` 的 `projection`（逐年收入/EBIT/FCFF），
  并写明驱动假设来自公司数据还是默认值（读 `assumption_sources`）。

### 5. 估值
- **只写区间，不写目标价。** 三情景 + WACC×永续增长率敏感性矩阵。
- DCF 隐含的 EV/EBITDA 与 P/E 要写出来，与常识区间（3–40 倍 / 5–60 倍）对照。
- 有可比公司倍数时（`comparable_pe` / `comparable_ev_ebitda` 由使用者提供），
  写 DCF 与可比法的差距并解释原因（`dcf_vs_comparable_gap`）。
- **可比倍数必须有来源**，禁止自行编造同业倍数。
- 压力情景不足时（`stress_diagnostic.insufficient`）必须写明"本次未构成实质压力"。

### 6. 风险因素
- 每条风险**必须附触发信号**：一个可观测的指标 + 阈值。
- 从 `forensic_scan` 的发现里取，连同 `counter_evidence`（反证方向）与
  `open_questions`（未解问题）一起写 —— 只写风险不写反证是不完整的。
- 风险要映射到估值参数（`valuation_links`），说明它影响哪个驱动变量。

### 7. 结论与待核验事项
- 结论用条件式：在什么假设下、价值落在什么区间。
- 待核验事项逐条列出，每条写"要核验什么 + 去哪里核验（哪份文件哪一页）"。
- 明确写适用边界：只覆盖已上传资料的公司、期间与口径。

## 交付前必须自检

```
audit_report(run_id, text=<备忘录正文>, forensic_run_id=..., valuation_run_id=...)
```

- **hard 问题必须全部修完并重跑一次**才能交付。
- 特别注意三类：
  - 未溯源金额 —— 备忘录里任何数字都要能在工具产出里找到；
  - 计数不符 —— 「N 项」必须等于工具字段；
  - 一票否决 —— 目标价、评级、收益保证一个都不能有。
- 交付时把 `competition_metrics` 的达标对照表一并给出。

## 纪律

- **每章都要有证据锚点**（页码 / 指标代码 / 证据 ID），让读者三次点击内回到原文。
- **明确区分事实、计算、推断、待核验**四层，不混在同一段里。
- **不补业务故事**：管理层没有解释的原因，写成待验证假设，不要替公司编。
- **篇幅服务于决策**，不追求页数。竞赛要的是"任取一个风险结论，三次点击以内
  看到原文页码、抽取值、计算式、同行基准和模型版本"。
- 本备忘录用于研究辅助，**不构成证券投资咨询或收益承诺**；这句免责声明要保留。
