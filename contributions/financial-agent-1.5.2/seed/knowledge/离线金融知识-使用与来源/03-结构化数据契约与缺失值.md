# 结构化数据契约与缺失值

标题：结构化数据契约与缺失值
任务域：跨任务离线准备与来源管理
关键词：JSON Schema 结构化提取 null 单位 期间 口径
适用范围：本项目工作流；具体会计与法律规定以对应来源版本为准
核验日期：2026-10-11
来源：https://json-schema.org/draft/2020-12/json-schema-core
资料性质：原创工程说明；官方链接仅支持对应格式或部署规范

本项目建议每个金融字段同时保存原文值、标准化值、单位、缩放因子、币种、期间、期间类型、合并范围、公司标识、出处、提取状态与转换步骤。仅有金额不能代表同一事实；同一数值在千元与元、季度与年度、母公司与合并报表中意义不同。

数据结构可用JSON Schema描述对象、数组和字段类型，但结构校验不能证明数字真实。字段缺失、明确未披露、不适用、无法读清和确为零是不同状态。null保留未知，零只能有原文或明确用户假设支持。JSON数字无法保存所有原文表示，涉及精度的金额建议保存Decimal字符串和原始显示值。

例如模拟金额“1,234千元”的原文值保留1,234，标准化值为1234000，scale为1000，转换操作留痕；EPS“1.23元/股”不能跟随整表千元标题再缩放。日期区间保存起止时间，不以文件名年份替代报表期间。单位识别来自页眉、表头、附注或单元格局部声明，冲突进入复核。

先校验结构再校验值域、类型、单位关系和证据可达性，最后才进行勾稽。项目的数据契约是工程约定，JSON Schema2020-12是所选结构描述规范，不能将它等同监管机关规定的财报格式。
