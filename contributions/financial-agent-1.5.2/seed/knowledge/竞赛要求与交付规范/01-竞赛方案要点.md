# 竞赛方案要点（FinSleuth 财证智鉴）

**竞赛**：2026 年北京市大学生金融人工智能竞赛
**项目名称**：FinSleuth 财证智鉴 — A股财报法证与估值压力测试智能体
**方案定位**：围绕一家公司的一次投研决策，把公告、财报、问询函、互动平台信息与行情数据
转换为可追溯证据，自动发现盈余质量和经营异常，完成同行验证、情景预测、估值压力测试，
并生成含风险边界的研究报告。

---

## 一、核心用户与核心决策

- **核心用户**：买方研究员、基金经理、投研团队
- **核心决策**：这家公司当前最值得核验的风险是什么，估值是否已计入该风险
- **竞赛优势**：同一条证据链同时证明金融专业性、智能体编排、可解释性与可复现性
- **推荐演示标的**：有完整年报、问询函或监管关注、同行可比公司明确的 A 股制造业公司

## 二、最低可交付版本（MVP 硬指标）

| 维度 | 最低要求 |
| --- | --- |
| 标的 | **单公司**（A 股非金融上市公司，优先制造业） |
| 时间 | **三期财报**（最近 3 个完整会计年度及最新一期） |
| 同行 | **五家**同行可比公司 |
| 异常指标 | **十类**异常指标 |
| 估值 | **三种**估值情景 |
| 交付 | **一键生成报告** |

不在范围：银行、保险、券商等资产负债表逻辑特殊行业；实时高频交易与分钟级预测；
付费研报全文与非授权爬取；自动交易、保证收益、精确目标价承诺。

## 三、成功判据（评委视角，四条）

1. 评委能在 **30 秒内**理解系统替谁解决什么问题。
2. 任取一个风险结论，**三次点击以内**看到原文页码、抽取值、计算式、同行基准和模型版本。
3. 修改收入增速、毛利率或资本开支后，利润表、自由现金流和估值**同时重算**，且勾稽关系不破坏。
4. **断网**后仍可完成全部演示；同一数据包连续运行两次，确定性数值完全一致。

## 四、交付物与验收标准

| 交付物 | 内容 | 验收标准 |
| --- | --- | --- |
| Web 原型 | 公司检索、任务进度、风险雷达、证据链、同行对比、估值沙盘、报告导出 | 离线演示可运行；关键任务不依赖临时网络 |
| 投研报告 | 15–25 页 PDF，含摘要、公司与行业、财务法证、盈利预测、估值、风险与证据附录 | 每个关键判断可回溯到原文页码和计算公式 |
| 代码与环境 | 前后端、Agent 编排、规则引擎、模型适配器、数据样例、测试 | 一条命令启动；固定种子和缓存可复跑 |

| 演示视频 | 不超过 5 分钟的 MP4（不超过 500MB） | 覆盖完整任务链、风险证据、估值变化和可复现机制 |

## 六、五层架构与禁令

```
用户请求 → Orchestrator 任务编排器
  → Data Agent 数据获取与版本化
  → Parse Agent 表格和文本结构化
  → Forensic Agent 财务法证规则与异常排序
  → Industry Agent 同行与产业证据
  → Forecast Agent 三表预测与情景假设
  → Valuation Agent DCF 与相对估值
  → Critic Agent 反证检查与报告评分
  → Report Agent 生成带引用的投研报告
→ Evidence Graph 证据图谱 + Run Ledger 运行账本
→ Web UI / PDF 报告 / 审计日志
```

| 层 | 职责 | **禁止事项** |
| --- | --- | --- |
| 数据层 | 原始文件只读存储、哈希、版本、来源和截止时间 | 覆盖原文件；丢失来源 URL 或页码 |
| 结构化层 | 表格识别、科目映射、单位与期间标准化 | 未记录映射置信度就写入标准事实表 |
| 计算层 | 公式、规则、同行分位、三表与估值 | **用 LLM 心算或生成最终数值** |
| 推理层 | 假设生成、文本归因、矛盾检测、反证 | 把推断伪装成事实；忽略相反证据 |
| 呈现层 | 风险雷达、证据阅读器、估值沙盘、报告 | 给出无免责声明的单点投资建议 |
| 审计层 | 记录模型、Prompt、工具、输入输出、耗时与错误 | 记录密钥或个人敏感信息 |

编排状态机：`CREATED → DATA_READY → PARSED → VALIDATED → ANALYZED → FORECASTED → VALUED → CRITIQUED → REPORTED`。
任一步失败进入 `RETRYABLE_ERROR` 或 `HUMAN_REVIEW`。
**只有通过 `validation_gate` 的数据才能进入分析；只有通过 `evidence_gate` 的结论才能进入报告。**

## 七、报告输出目录（15–25 页 PDF 的九章结构）

1. 投资结论与适用边界
2. 公司与行业概览
3. 关键经营驱动
4. 财务法证发现
5. 管理层解释与反证
6. 盈利预测与情景假设
7. 估值与敏感性
8. 催化剂、风险与待核验问题
9. 证据索引、公式、数据与模型说明

## 八、答辩常见追问与回答骨架

| 问题 | 回答要点 |
| --- | --- |
| 为什么不用通用大模型直接读年报 | 数值由确定性工具计算；LLM 负责抽取、归因与解释；证据门和 Critic 控制幻觉 |
| 异常是否等于财务造假 | **不等于**。系统输出需核验的风险信号，并列替代解释与反证 |
| 同行怎么选 | 先按行业与业务相似度筛，再按规模、地区和收入结构；显示选择规则并允许剔除 |
| 估值为什么可信 | 所有假设有来源；三表勾稽；输出区间与敏感性；风险直接映射到参数 |
| 如何证明可复现 | 固定数据快照、哈希、Prompt 版本、模型版本、随机种子和运行账本 |
| 本地模型不够强怎么办 | 把高风险任务拆成结构化子任务；**核心数值不依赖模型**；缓存只复现已记录结果 |
| 创新在哪里 | 把法证规则、证据图谱、反证 Agent 和估值压力测试连接成**同一决策闭环** |

## 九、一票否决项（报告评分量表）

- 关键数字错误（事实正确维度）
- **伪造引用**（证据充分维度）
- 三表不平或因果倒置（金融逻辑维度）
- 收益保证或确定性荐股（风险审慎维度）
- 只有摘要、没有决策支持（可操作性维度）

## 十、伦理与合规声明要点

- 本系统用于研究辅助，**不构成证券投资咨询或收益承诺**。
- 所有数据均标注来源、授权条件、截止日和处理方式。
- 模型生成内容必须经过证据门和人工复核后才能外发。
- 系统不得处理未公开重大信息，不得绕过网站访问控制。
- 第三方模型、框架、接口和数据分别列明版本、许可证和使用范围。
